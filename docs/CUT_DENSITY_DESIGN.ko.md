## 1. 화면 크기에 연동해 공간을 합친다

사용자 후속 설명에 따라 **레이어 전체에 최소 한 점**이라는 최초 가정은 철회한다.
기준은 현재 화면에서 일정한 크기를 차지하는 공간 구역이다. 배율이 줄면 구역의 세계좌표 크기가
커지고, 가까워진 도형들의 기여를 먼저 합친 뒤 점 수를 결정한다.

예를 들어 세계좌표에 고정된 계층 격자를 사용하고, 조회한 한 칸이 화면에서 8~16 px 폭이 되도록
깊이를 고른다. 선형 배율을 절반으로 줄이면 자식 2×2칸이 부모 한 칸으로 합쳐진다.
8 px는 첫 실험값이며 제품 기본값으로 정한 것이 아니다.
구역이 포개지는 것과 최종 점의 포함 관계는 별개다. 특히 레벨별 디더 문턱을 독립적으로
정하면 같은 배율의 재실행은 결정적이어도, 레벨 전환 때 점이 다시 생기거나 위치가 바뀔 수 있다.

```
원본의 면적/공간 정보 → 현재 배율의 공간 구역에 누적 → 구역 안에서 점으로 양자화
```

도형·페이지·인스턴스별로 점을 먼저 만든 뒤 합치지 않는다. 예를 들어 **현재 배율에서** 각각
0.2 px²에 해당하는 기여 네 개가 같은 구역에 있으면, 각각 반올림하여 0개로 버리는 대신
0.8 px²를 합쳐 약 1점을 낼 수 있다. 이는 이전 배율의 면적을 축소 보정 없이 더한다는 뜻이 아니다.

## 2. 물리적 밀도와 저밀도 존재 보정

**면적에 따른 밀도 표현**과 **존재를 알리는 최소 한 점**은 별도 규칙이다.

세계좌표에서 같은 영역 R과 그 안의 도형 합집합 S를 보면:

- 밀도 `rho = area(S) / area(R)`는 배율이 바뀌어도 같다.
- 화면에서의 실제 덮임 `M = area(S) * scale^2`는 배율의 제곱으로 줄어든다.
- 1픽셀 점으로 표현할 목표 점 수는 `N_area ≈ M`이다. 한 도형에 한 점을 주지 않는다.

동일한 내용을 선형 배율 100%, 50%, 25%, 12.5%, 6.25%로 보면, 기준 덮임이
256 px²인 예에서는 점 수가 대략 **256 → 64 → 16 → 4 → 1**이 된다.
뷰포트 크기는 고정하고 동일한 내용을 더 작게 투영한 예다. 축소하며 새로운 도형이
뷰에 들어오거나 다른 도형이 컷 아래로 편입되면, 전체 점 수가 꼭 줄지는 않는다.

`M < 1`인데도 점 하나를 보장하면 엄밀한 면적 보존은 불가능하다. 따라서 마지막
한 점은 밀도를 더 높게 계산한 결과가 아니라 **존재 표시라는 명시적 예외**다.
그 점도 원래 내용이 도달하는 픽셀에 놓고, 크기를 늘리지 않는다.

순수 면적 누적만으로는 극단적인 축소에서 마지막 점까지 없어진다. 이를 막는 보정도
**현재 배율에서 합쳐진 구역 단위**로 적용한다. 페이지·레코드·반복 멤버·소스 BVH 노드·
래스터 타일 각각에 최소 한 점을 주지 않는다.

구역 q의 점 수는 다음과 같다. `M_q`는 구역의 합집합 면적을 화면에 투영한 값이다.
면적을 정수화할 때는 구역별 반올림 대신 **세계좌표에 고정된 디더 문턱**을 사용한다.

```
u_q = hash(고정 seed, 레이어, 공간 레벨, 세계좌표 구역 키) → [0, 1)
N_area,q = floor(M_q) + [u_q < frac(M_q)]
N_q = max(N_area,q, 존재 표시 자격이 있으면 1 아니면 0)
```

균일한 문턱에 대한 기대값은 `E[N_area,q] = M_q`다. 같은 질량 1.51을 가진 구역들이
모두 2점으로 반올림되는 편향을 줄인다. 단일 seed의 합계가 면적과 정확히 같다는 뜻은 아니며,
출력 픽셀 충돌도 점 수를 줄일 수 있다. 프레임마다 seed를 바꾸지 않고, 면적에 따른 점 수·
존재 보정의 추가 점 수·출력 픽셀 충돌을 따로 센다. 존재 보정은 `M_q < 1`인 자격 구역에서
면적 정수화가 0이 되었을 때만 추가한다. 그런 구역은 중간 배율의 경계에도 있으므로
"12.5% 이하에서만 보정된다"는 전역 배율 규칙은 아니다.

- 자격은 내용이 있는 구역의 덮임 비율 `rho_q >= tau`로 판단하는 것을 먼저 실험한다.
  `tau`는 아직 제품 기본값으로 정하지 않는다. 보정하지 않아도 면적 누적으로 점이 나올 수 있다.
- 최소 보정이 추가하는 것은 구역당 많아야 1점이다. 충분히 펼쳐진 저밀도 영역에서 한 칸의
  폭이 최소 8 px이면 보정만으로 생기는 점은 칸당 최대 1/64의 픽셀 비중이다. 저밀도 보정
  자체로 넓은 밝은 박스를 만들지 않으며, 실제 밀도가 높은 곳은 별도로 더 많은 점이 나올 수 있다.
- 축소하며 4칸을 한 칸으로 합치면 최소 보정도 4개를 더하지 않고 새 구역에서 한 번만 결정한다.
  경계에서 서로 같은 출력 픽셀을 택한 점도 합친다.
- 설계 전체가 한 구역보다 작아진 뒤에도 화면의 빈 바깥까지 분모에 넣으면 밀도가 계속 떨어진다.
  실험에서는 고정된 레이어 데이터 범위와 구역의 교집합을 분모로 사용한다. 전체가 한 구역에
  들어온 뒤 그 내용의 밀도가 기준 이상이면 마지막 점이 남는다. 한 점 아래의 빈 공간 비율까지
  정확히 보존할 수 있는 것은 아니다.
- 최소 점도 현재 뷰·레이어·depth·컷 아래 내용에 속해야 한다. 화면 밖 내용을 이유로 찍지 않는다.
- 점은 실제 점유 위치의 안정적인 anchor를 사용한다. bbox 중심이나 면적 중심은 빈 곳일 수 있다.
- 위 레이어에 가려진 경우까지 점을 강제로 드러내지는 않는다. 레이어 순서는 유지한다.

고정된 레이어 데이터 범위의 정의(depth·크기대·멀리 떨어진 군집 포함), 밀도 문턱,
칸 폭과 저밀도 강조량은 시각 실험으로 정할 항목이다. 모든 낮은 밀도를 무조건 살리는 규칙은 아니다.

## 3. 빈 공간을 어떻게 보존할 것인가

총 면적 스칼라 하나만으로 bbox 전체에 점을 뿌리지 않는다. 두 덩어리 사이의 큰 빈 통로까지
채워 버릴 수 있다. **공간별 덮임 비율과 빈 영역 정보**가 필요하다.

- 각 출력 픽셀의 목표값은 그 픽셀이 덮는 실제 도형 합집합의 면적 비율이다.
- 빈 통로가 화면에서 구분 가능한 동안은 해당 구역에 점을 내지 않는다.
- 간격이 픽셀보다 작아진 뒤에는 개별 간격의 모양 대신, 여러 픽셀에 걸친 점/빈 픽셀 비율로
  밀도를 나타낸다. 모든 미세한 구멍의 위치를 끝까지 보존한다는 뜻은 아니다.
- 부모 요약은 자식의 빈 공간을 포함한 면적으로 가중 평균한다. 비어 있지 않은 자식만 평균하거나
  자식 점유를 OR하여 부모를 1로 만드는 방법은 쓰지 않는다.
- 같은 레이어에서 겹친 도형은 면적 합이 아니라 합집합이다. 중복 도형이나 중복 배치가
  밀도를 높여서는 안 된다. 서로 겹치는 요약의 비율을 단순 합산 후 clamp하는 것으로는
  합집합을 구할 수 없다. 작은 이산 마스크 또는 더 세밀한 공간 정보가 필요하다.

헤어라인은 실제 폭 × 길이(일반 도형은 면적)로 기여한다. 폭을 먼저 1 px로 올리지 않는다.
폭이 0인 기하를 어떻게 취급할지는 별도 표시 정책이며, 이 설계에서 임의의 면적을 주지 않는다.

## 4. 점의 배치와 안정성

독립 난수로 픽셀을 켜는 것만으로는 저밀도 영역의 점이 모두 사라질 수 있다.
공간 구역별로 합집합 면적을 누적하고 점 수를 정한 뒤, 구역 안의 덮임에 맞게 점을 분배한다.

- 고정된 세계좌표·레이어·공간 키에서 결정되는 순위를 사용한다. 프레임 번호, 작업자 번호,
  페이지 분할이나 paint 완료 순서를 난수 키로 쓰지 않는다.
- 점 수가 줄면 안정적인 순위의 앞부분만 유지하고, anchor는 그 첫 점과 공유한다.
  최소 표시로 바뀔 때 다른 위치에 새 점이 튀어나오는 것을 피한다.
- 출력 픽셀의 충돌은 하나로 합친다. 세계좌표 표본의 포함 관계와 최종 픽셀의 포함 관계는
  다르므로, 이것만으로 pan/연속 줌의 무점멸을 보장했다고 주장하지 않는다.
- 공간 노드가 합쳐질 때 면적과 대표 anchor를 상속한다. 부모와 자식을 동시에 표시하지 않는다.
- 독립적인 `(레벨, 구역 키)` 해시는 정수화 편향을 확인하는 첫 대조군이다. 그것만으로
  줌에 따른 점 수의 단조 감소나 한 번 사라진 점의 재등장 방지를 보장하지 않는다.
  부모·자식의 문턱/순위를 연계하는 방식과 연속 줌 전환을 별도로 검증해야 한다.
- 격자는 화면/타일 원점이 아니라 고정된 설계 범위에 고정한다. 계층의 루트는 그 범위를
  포함해야 한다. 셀 인스턴스마다 따로 출력 격자를 만들어 최소 보정을 중복 적용하지 않는다.
- 확대 시 고정된 전역 표본만 계속 키우는 OVR 방식은 사용하지 않는다. 요약을 더 세밀하게
  조회해 가시 영역의 밀도를 재구성할 수 있어야 한다.

면적 보존, 공간 분포, 연속 줌 안정성을 동시에 만족하는 배치법은 작은 실험에서 먼저 비교한다.
세계좌표에 고정된 공간 분배와 계층별 순위가 후보이며, 타일별 독립 최소 점은 금지한다.

### 4.1 부모 min 문턱: 포함 관계의 후보와 한계

후속 제안의 **앵커 선택 문턱 T**와 §2의 **정수화용 난수 문턱 u**는 다르다.
`u`를 낮추면 반올림으로 올라갈 가능성이 커지지만, `rank < T`의 `T`를 낮추면
생존 앵커가 줄어든다. 기존 `u`에 그대로 min을 적용하는 변경으로 해석하지 않는다.

다음 조건에서 제안의 포함 관계는 성립한다.

```
A_parent = 자식들의 고정 세계좌표 앵커 후보 집합의 합집합
S_q = { a ∈ A_q : rank(a) < T_q }
T_parent = min(T_parent_own, 후보가 있는 자식들의 T_child 최소)
```

부모가 고른 앵커 a는 자신이 속했던 자식에서도 같은 rank로 `rank(a) < T_child`를
만족하므로 `S_parent ⊆ ∪ S_child`다. 후보와 순위가 레벨마다 새로 만들어지면 이 증명은
성립하지 않는다. 픽셀 위치의 포함 관계나 점멸 방지까지 증명한 것도 아니다.
레이어·depth·컷 아래 내용과 가시 범위가 같은 대상을 비교한 조건이며, 줌아웃하며 새 도형이
컷 아래로 들어오는 상황의 전체 점 집합에 무조건 적용하지 않는다.

비용과 품질은 별도 조건이다.

- 후보가 없는 자식은 min에서 제외하거나 중립 문턱을 쓴다. 빈 자식의 0 때문에 부모 전체가
  사라져서는 안 된다. 내용은 있으나 밀도가 낮은 자식도 형제들의 문턱을 낮추므로,
  과소 표현을 "조금"으로 제한할 일반적인 보장은 없다.
- 반례: 자식마다 고정 앵커 후보가 100개, 목표 질량이 80/80/80/1점이면 선형 반배 축소의
  부모 질량은 60.25점이다. 부모 자체 문턱은 60.25/400 = 0.150625지만 자식의 최소 0.01로
  제한하면 균등한 rank에서 **4점**만 남는다(면적보다 93.36% 적다). 포함 관계는 맞지만
  밀집한 형제까지 지나치게 어두워진다. 이 규칙은 비교 후보이며 기본안으로 확정하지 않는다.
- 구역의 최소 rank 앵커가 모든 조상에서도 최소인 것은 아니다. 이웃 구역에 더 낮은 rank가
  있으면 병합할 때 그쪽이 대표가 된다. 올바른 상속 방향은 **부모가 선택한 대표가 어느 자식에서
  이미 보였는지**다. 자식마다 보장한 점을 모두 조상까지 살려 두지는 않는다.
- 존재 보정은 위의 `rank < T` 밖에서 점을 추가하므로 증명에 포함되지 않는다. 부모의 최저 rank가
  자격 미달로 비어 있던 자식에서 오면 새로 등장한다. 먼저 자식에서 실제로 살아 있던 앵커 중
  부모 대표를 고르는 방식을 비교한다. 앵커 자격의 계승과 밀도 문턱의 정책을 함께 검증한다.
- 저장한 문턱을 읽고 **한 앵커**를 판정하는 것은 O(1)이지만, 후보를 찾아 점 N개를 내는 조회는
  별도다. 최소한 출력 N에 비례하며, rank/공간 조회 구조가 없으면 후보 전체 열거가 남는다.
  고정 4096개 표본을 쓰는 아래 오라클을 제품용 전역 표본 상한으로 옮기지 않는다.

다음 비교 후보는 자식에서 이미 선택된 앵커의 합집합에서 부모의 목표 수만큼 rank 순으로
남기는 방식이다. 성긴 형제가 다른 형제의 문턱을 직접 낮추지는 않지만, 자식 생존자의 부족,
존재 보정, 공간 쏠림과 조회 비용을 다시 검증해야 한다. 아직 제품 알고리즘으로 결정한 것은 아니다.

## 5. detail과 원본 경계

현재 plain layout의 thin keep은 `shape_cut`을 페이지 선택과 도형별 래스터에 전달한다.
medium에서는 현행 3 px 컷을 그대로 사용한다. 이 단계에서 1 px 컷이나 긴 선 예외는 추가하지 않는다.

- 컷 이상의 도형은 기존 원본 경로로 보낸다.
- 컷 아래는 헤어라인을 포함해 밀도 경로로 보낸다.
- 큰 도형과 작은 도형이 섞인 페이지에서 잘린 작은 도형도 밀도에 포함한다.
- 전체가 잘린 페이지와 같은 역할이며, 디코드 여부로 밀도 포함 여부가 달라져서는 안 된다.

컷 문턱을 넘을 때 존재가 사라지는 것은 막을 수 있지만, 원본의 윤곽선·스페클과 면적 밀도 사이의
밝기 변화까지 자동으로 연속이 되지는 않는다. 별도 경계 실험에서 판단한다. 필요하면 컷 아래의
좁은 구간에서 요약 해상도를 더 높여 공간 변화부터 줄이며, 컷 아래 원본 전체 디코드로 돌아가지 않는다.

detail은 요약의 공간 오차 허용치·조회량에도 적용한다. medium의 컷이 더 크다고 항상 high보다
빠르다는 보장은 없으며, 실제 전체 시간을 비교한다. 예산이 부족하다고 bbox를 채우지 않는다.

## 6. 인덱스와 렌더 연결

원본을 매 프레임 다시 읽어 덮임을 계산하는 방식은 **시각 오라클**에만 사용한다.
제품 경로는 컷 아래 내용을 디코드하지 않고 읽을 수 있는 공간 요약이 필요하다.

### 6.1 광역뷰와 가까운 뷰의 조회 경로

**광역뷰의 밀도 조회는 인스턴스 수만큼 걷지 않아야 한다.** 셀 로컬 요약을 공유하더라도
매 프레임 배치마다 변환·합성하면 MAIN01의 수억 배치에 비례하는 비용이 남는다.

- 광역뷰용 레벨은 인덱스 때 top 공간에 평탄화하거나, 큰 서브트리의 재귀 요약으로 미리
  합성한다. 후자의 경우에도 뷰어가 수많은 서브트리 인스턴스를 다시 열거하지 않고
  상위 공간 요약에서 멈출 수 있어야 한다. 단순히 leaf 셀 요약을 캐시하는 것으로 충족되지 않는다.
- 가까운 뷰는 가시 범위를 공간 트리로 먼저 제한한 뒤 셀 로컬 공유 요약과 페이지/공간 트리
  요약을 조회한다. MAIN01은 얕은 depth에 자체 도형이 많으므로 TOP 자체 도형도 별도로 덮는다.
- 두 경로가 전환되는 범위에서 같은 밀도와 빈 통로가 유지되는지 비교한다. 광역 데이터가
  없거나 예산을 넘었다고 인스턴스 전체 열거·원본 전체 디코드로 자동 복귀하지 않는다.
- 표시할 셀을 고른 뒤에만 출력 점을 만든다. 박스 목록이나 인스턴스별 점 목록을 중간 산출물로
  만들지 않는다. 조회 노드·반복 범위·요약 바이트·메모리도 함께 예산을 둔다.

크기대별 조회가 가능해야 원본과 컷 아래 도형을 구분할 수 있다. 전체 레이어 덮임을 무조건
더하면 컷 이상의 원본 스타일의 빈 픽셀까지 바뀔 수 있으므로, 이 초안은 컷 아래 요약을 기준으로 한다.
depth, 반복, 회전·반사, 겹침 합집합, 좁은 선의 면적 손실을 검증한다. 생성이 O(records)라고
지금 확정하지 않는다. OVM v9 또는 별도 파일 중 저장 형식은 생성 시간·크기·오차를 잰 뒤 결정한다.

### 6.2 기존 occupancy 피라미드의 재사용 평가

**비율값·크기대 선택이 가능한 광역 요약의 우선 비교 후보로 삼되, 기존 OVO의 단순 확장으로
채택했다고 보지는 않는다.** 근거는 [OCCUPANCY_PLAN](OCCUPANCY_PLAN.ko.md),
`rust/vfs/src/occupancy.rs`, `render-core/src/summary.rs`, `raster.rs::paint_summary_plane`다.

- 기존 OVO2는 `(레이어, 배치 depth)`별 top 공간 비트맵을 인덱스 때 만든다. 상위 레벨은 2×2 OR,
  제한 depth는 해당 깊이까지의 평면 OR다. 중복 도형을 여러 번 세지 않는 **교차 여부의 합집합**은
  맞지만, 비트 1은 작은 양의 면적 교차도 뜻한다. 셀 ≤ 1 px 조건은 화면 오차를 제한할 뿐,
  얇은 선과 빈 공간의 실제 면적 비율을 복원하지는 못한다.
- 비율 요약의 부모는 OR 대신 빈 공간을 포함한 면적 가중 평균이어야 한다. 기존 level 0 비트를
  평균내는 것만으로는 level 0에서 이미 잃은 미세한 면적·간격이 복구되지 않으므로,
  덮임 계산이나 더 세밀한 마스크를 인덱스 생성 단계에서 마련해야 한다.
- **크기대끼리와 depth끼리도 합집합**이어야 한다. 비율값만 저장한 두 평면은 서로 어디가
  겹치는지 모른다. 단순 합산/clamp는 불가다. 요청 조합의 합집합을 미리 계산한 누적 평면,
  또는 합집합을 계산할 수 있는 세부 공간 정보를 비교한다. 일반적인 작은 표본 마스크는
  아주 얇은 선을 놓칠 수 있으므로 선의 면적 보존도 따로 판정한다.
- 화면 타일로의 투영·레이어 선택·depth 키·파일 유효성 검사는 재사용 후보다. 현재 요약은
  선택 레이어의 원본 페이지를 통째로 대체하지만 새 경로는 원본과 컷 아래 밀도가 공존한다.
  원본 fill 스타일과 윤곽선 생성도 새 밀도 점 패스에 그대로 적용하지 않는다.
- 현재 `paint_summary_plane`은 타일 범위의 선택 레벨만 조회한다. 그러나 `planes_for`의
  첫 depth 합성은 선택 레벨의 **전체 평면을 OR하고 캐시**한다. 새 경로의 cold 조회도 무조건
  화면 픽셀 수에만 비례한다고 주장하지 않는다. 큰 평면은 요청 공간 타일만 읽고 합성하도록
  검토하며, 첫 열기·depth 변경 때의 읽기와 할당도 측정한다.
- 기존 plain 레이아웃 occupancy의 생성 시간·용량 문제는 미해결 입력 조건이다.
  기존 피라미드가 있다는 이유로 새 비율 요약의 인덱싱이 빠를 것이라고 가정하지 않는다.

### 6.3 저장량과 연속 컷 경계

`s = px / dbu`라면 medium의 세계좌표 컷은 `3 / s` dbu이며 줌에 따라 연속으로 변한다.
**첫 저장 실험의 기본안은 크기대·depth를 함께 조건으로 한 누적 합집합 평면**이다.
각 공간 구역 R에 대해 다음을 저장하는 방향으로 비교한다.

```
F[k,d](R) = area(R ∩ union{도형 : 작은 변 < b[k], 배치 깊이 ≤ d}) / area(R)
```

`b[k]`는 파일에 저장한 크기 경계다. 1옥타브 기본 모형은 `b[k] = 2^k`이고,
아래의 공통 컷 실험에서는 반/1/4옥타브 간격도 비교한다.

고정 d에서 k가 커지면, 고정 k에서 d가 커지면 포함 관계가 된다. 컷이 저장 경계와 일치하면
해당 누적 평면 하나만 조회하고, 분리된 크기대의 비율값을 런타임에 합산하지 않는다.
별도의 크기 누적 평면과 depth 누적 평면을 만들고 비율값을 결합하는 것으로는 안 된다.
작고 깊은 도형과 크고 얕은 도형이 같은 픽셀을 덮으면 양쪽 개별 평면은 모두 1이어도
"작고 얕은 도형"의 합집합은 0일 수 있다. 따라서 기본 비교 단위는 **공동 조건 F[k,d]**다.

같은 공간 해상도·정밀도를 조밀하게 저장할 때 크기 평면 수는 분리 대와 같은 B개다.
다만 누적 평면은 상위 경계에서 더 많은 공간이 비어 있지 않게 되고, depth까지 공동으로
저장하면 B×D 조합이 남는다. 압축률·동일 타일 공유·생성 work까지 불리하지 않다고 보장하지 않는다.

**인접 누적 평면의 로그 보간은 오차가 유계인 근사이지, 누수·누락이 없는 컷 판정이 아니다.**
컷 c가 `[2^k, 2^(k+1)]` 사이일 때 `a = log2(c / 2^k)`로 두면:

```
F_interp = (1-a) F[k,d] + a F[k+1,d]
F[k,d] ≤ F_exact(c,d) ≤ F[k+1,d]
|F_interp - F_exact| ≤ max(a, 1-a) × (F[k+1,d] - F[k,d])
```

이 경계는 원본의 정확한 누적 덮임에 대한 값이다. 저장 정밀도·공간 근사 오차는 별도로 더해진다.
두 평면의 차이는 1에 가까울 수 있으므로 유계라는 말이 작은 오차를 뜻하지 않는다.
예를 들어 작은 변 10인 사각형 내부에서 F[3]=0, F[4]=1이다. 컷 9는 실제 밀도 대상이 아닌데
보간하면 **0.169925**의 덮임이 생기고, 컷 12는 전부 대상인데 **0.584963**만 나온다.
도형 크기 분포가 경계 대 안에 몰리면 실제 누적 덮임은 계단형이므로 로그 보간으로 복원할 수 없다.

현재 제품의 도형별 원본 컷은 그대로이며, 아래 양자화안은 아직 설계·오라클 단계다.
원본 컷을 그대로 둔 채 밀도만 미리 보간하면 아직 원본으로 그리는 도형의
빈 스타일 픽셀까지 달라질 수 있다. 보간은 의도적인 혼합 구간을 허용할 때의 비교안으로 남기며,
"컷 아래만" 규칙을 만족하는 기본 조회로 채택하지 않는다. 첫 연결 실험에서는 다음의 공통
양자화 컷을 우선 비교하고, 전환 품질·원본 비용·저장량을 함께 결정한다.
이를 피하려고 컷 아래 원본 전체 디코드를 다시 허용하지 않는다.

depth는 정수 단계이므로 요청 d에 해당하는 누적 평면을 선택한다. 두 depth 사이를 보간하면
요청보다 깊은 도형이 섞이므로 사용하지 않는다. 동일한 결과인 depth만 공유할 수 있다.

#### 공통 양자화 컷 — 첫 연결 실험의 우선안

요청 컷 이하에서 가장 가까운 저장 경계를 **실제 적용 컷**으로 선택하고, 원본과 밀도가
같은 값을 사용한다. 이는 원래의 연속 컷을 정확히 재현하는 것이 아니라 detail의 컷 정책을
계단형으로 바꾸는 선택이다. 보간 없이 한 누적 평면을 읽을 수 있다.

```
c_requested = ceil(detail_px / px_per_dbu)       # 현재 renderd의 DBU 변환
c_effective = max{ b[k] : b[k] <= c_requested }
원본 대상 = { 도형 : 작은 변 >= c_effective }
밀도 대상 = { 도형 : 작은 변 <  c_effective }   # F[k,d]
```

정상적인 양의 면적 도형에 대해 두 대상 집합은 서로 겹치지 않고 합이 전체다. 경계와 같은
도형은 원본에 속한다. **도형의 소속 분할**에 대한 보장이며 서로 다른 도형의 실제 좌표 겹침,
밀도 양자화로 의도적으로 비는 픽셀, 레이어 가림까지 없어지는 것은 아니다.

구현 조건:

- 경계는 인덱스에 단조 증가하는 정수 DBU 표로 저장하고, 뷰어는 이 표에서 직접 선택한다.
  인덱서·뷰어가 각자 `pow`와 반올림으로 경계를 재생성하지 않는다. 반/1/4옥타브를 DBU로
  바꿀 때 생기는 중복 경계는 합치고, `<` 비교 규칙·단위·depth를 양쪽에서 일치시킨다.
- **페이지·페이지 BVH·계층 프루닝부터 래스터의 `shape_cut`까지 같은 유효 컷을 사용한다.**
  요청 컷 12로 작은 변 10뿐인 페이지를 먼저 버린 뒤 래스터와 밀도만 컷 8을 쓰면,
  원본에서도 사라지고 컷 8의 밀도 평면에도 없어 빈틈이 생긴다. 계층 프루닝의 hairline 계수 등도
  남길 도형을 잘라내지 않는 보수적인 판정인지 확인한다. 도형 크기의 정의는 현재처럼
  rect의 w/h, polygon·path의 한 멤버 bbox에 맞춘다.
- 양자화는 플랜 전에 결정하고, 최종 플랜이 사용한 유효 컷과 평면 ID를 래스터·밀도 패스에
  함께 전달한다. 스타일 변경·프레임 캐시·pan 재사용에도 요약 identity와 유효 경계를 반영한다.
  exact/컷 0은 밀도와 양자화를 사용하지 않는다. 지원 경계가 없거나 요약이 없는 상태를
  빈 평면과 혼동하지 않는다.
- 현재 `plan_hier_thinned`/`thin_to_budget`는 컷 이상의 페이지도 디코드 예산 때문에 제거할 수
  있다. 그 도형은 컷 아래 F[k,d]에 없으므로 **공통 컷만으로 예산 생략까지 해결되지는 않는다.**
  밀도 연결 실험에서는 페이지를 임의로 솎는 대신, 예산을 맞출 때 저장 경계 중 더 높은
  공통 컷으로 원본·밀도를 함께 옮기는 안을 우선 검토한다. 이는 요청 컷의 내림 양자화와
  별도의 예산 완화이며 상태줄에 구분한다. 기존 제품의 예산 정책은 이번 문서 수정으로 바꾸지 않는다.
- 예산 재계획에서도 최종 컷이 저장 경계여야 한다. 높은 컷으로 플랜을 만든 다음 밀도만
  아래 경계로 내리거나, 재계획 뒤에도 처음 고른 평면을 사용하는 방식은 금지한다.
  크기대만으로 페이지 예산을 맞추기 어려운 혼합 페이지의 비용은 별도로 계측한다.

크기 경계 간격을 h옥타브로 두면, 저장 범위 내부에서 DBU 반올림을 무시할 때
`3 / 2^h < c_effective × s <= 3`이다.

| 간격 h | medium의 실효 컷(px) | 같은 크기 범위의 평면 수(대략) |
|---|---:|---:|
| 1옥타브 | 1.50 초과 ~ 3 | 1배 |
| 1/2옥타브 | 2.12 초과 ~ 3 | 2배 |
| 1/4옥타브 | 2.52 초과 ~ 3 | 4배 |

1/4옥타브를 첫 품질/시간 대조의 기준으로 삼고 1/2옥타브와 비교한다. 아직 제품 기본값으로
확정한 것은 아니다. 평면 수 배율은 끝점·DBU 중복·빈 평면 공유·압축을 제외한 근사이며,
실제 저장 바이트가 반드시 2배/4배인 것은 아니다.

컷을 내리면 3px 미만 중 일부가 원본으로 남으므로 원본 디코드/래스터 비용은 늘 수 있다.
그 좁은 크기 구간에 반복 멤버가 몰리면 증가량은 매우 클 수 있고, 문턱이 최대 약 16% 낮아진다는
사실이 작업량 증가의 상한은 아니다. 페이지 선택 수·디코드 메모리·레코드/멤버 처리량·전체 시간을
기존 3px 컷과 high 모두에 대해 비교한다.

경계를 촘촘히 하면 전환되는 크기 폭은 줄지만, 같은 크기 도형이 많은 레이어는 여전히 한꺼번에
원본에서 밀도로 바뀔 수 있다. 컷 전후의 밝기·점 위치·형상 전환이 부드럽다는 보장은 아니며,
줌인/줌아웃 양방향과 경계 근처의 작은 배율 변경을 오라클에서 비교한다.

#### 저장량 판정

각 공간 레벨에 모든 크기대와 depth 평면을 조밀하게 두면 대략 다음 크기가 된다.
`Q0`는 기본 격자 칸 수, `L`은 레이어 수, `B`는 크기대 수, `D`는 깊이 수,
`a`는 칸당 바이트다(피라미드의 반올림·메타·anchor 등은 제외).

```
S_dense ≈ (4/3) × Q0 × L × B × D × a
```

예를 들어 기본 2048²칸, 449레이어, 8크기대, depth 0~15의 16평면, 칸당 1바이트만으로도
약 **299 GiB**다. 실칩의 실측 크기가 아니라 조밀한 직적곱 설계의 비용 예다. 또한 낮은 비율을
1바이트로 먼저 양자화해 0으로 만들면 나중의 공간 병합으로 복원할 수 없다. 저장 정밀도와
부분 면적/존재 anchor의 비용을 용량 계산에 넣어야 한다.

모든 조합을 반드시 이렇게 저장해야 하는 것은 아니다. 다음 대안을 함께 평가한다.

- 내용이 있는 공간 타일·크기대·depth만 저장하고 동일 평면을 공유한다. 압축 후 크기뿐 아니라
  조회 때의 해제 메모리와 최악 입력도 잰다.
- 각 공간 해상도에서 detail의 컷에 필요한 크기 범위만 둔다. 공간 레벨과 크기대의 전 조합을
  만들지 않되, 실제 연속 컷의 경계 오차를 명시한다.
- 광역에서만 조밀한 사전 합성을 쓰고 세밀한 공간은 가까운 뷰의 지역 요약으로 전환한다.
- 기본안인 공동 누적 합집합 F[k,d]의 타일 공유와 선택적 체크포인트를 비교한다.
  비율값의 차분이나 합만으로 임의 조합의 겹침 문제가 해결된다고 가정하지 않는다.

첫 파일 실험에서 저장량/생성 work/최대 메모리의 추정과 실측을 출력한다. 상한을 넘으면
기존 ICE를 유지하고 요약 생성 실패·지원 범위를 명시한다. 표시하지 못한 데이터를 빈 내용으로
취급하거나 깊이가 다른 요약으로 대신 그리지 않는다.

### 6.4 취소와 시간 계측

**요약 조회는 짧은 작업 단위마다 취소 가능해야 하며, 취소 확인 사이의 작업량도 유계여야 한다.**
시작 전·공간 타일/노드 배치 사이·합성 배치 사이·게시 전에 generation을 확인한다.
한 거대 반복 레코드나 전체 평면 병합이 그 경계를 우회하지 않게 한다. I/O, 메모리 해제,
캐시 교체도 긴 구간이 될 수 있으므로 취소 완료까지 실제 지연을 측정한다.

- 출력 예산은 노드/바이트 수처럼 결정적인 기준으로 적용한다. 경과 시간이나 워커 순서에 따라
  서로 다른 prefix를 정상 완료 프레임으로 내보내지 않는다. 필요하면 검증된 더 거친 요약을
  사용하며, 이미 대체된 generation은 결과를 게시하지 않는다.
- 확인된 현재 코드: `hier.rs::plan_hier` 내부에는 취소 지점이 없고, renderd의 일반 keep 경로는
  `cache.plan` 뒤에 취소를 확인한다. `rust_render.py`의 `wait_ms`는 상수 0이다. 따라서 이전 요청의
  계획이 다음 요청을 지연시킬 수 있으며 현재 상태줄로는 그 대기를 구분할 수 없다.
- 그렇다고 MAIN01의 미계측 15.5초가 모두 대기였다고 확정하지 않는다. 사용자는 조작을 멈추고
  기다린 뒤 한 번만 바꿔도 반복된다고 답했다. margin 배경 요청은 별도로 남을 수 있고,
  현재 `raster_us` 이후의 로컬 bin 해제, 캐시 관리·장면 교체 등도 단계 타이머 밖에 있다.
  `plan_us`는 해당 프레임의 거친 단계 재계획까지 포함한다.
- 새 뷰어에서 중간 줌 없이 같은 뷰로 직접 이동하고 margin을 끈 대조는 대기 가설을 좁히는 데
  유용하다. 7초 안팎으로 줄었다는 시간만으로 cold/warm·뷰 차이까지 배제되지는 않는다.
  요청 수신→작업 시작, 서버 전체 wall, 요약 조회 wall, 해제/게시, 클라이언트 수신을 따로 재어
  합계를 맞춘다. 전체 시간에서 알려진 단계의 합을 뺀 값을 곧바로 wait로 기록하지 않는다.

### 6.5 레이어 순서와 실칩 판정

레이어 블록 렌더와 연결할 때는 **레이어 L의 원본 → L의 밀도 → 다음 레이어** 순서로 그린다.
후처리로 프레임 끝에 붙이지 않는다. 밀도가 실제로 켠 점만 write-once 마스크에 기록한다.
요약 bbox 전체나 확률값을 가림으로 사용하지 않는다. 그래야 다음 블록의 디코드 생략에도 안전하게
기여한다. 같은 블록 안의 하위 레이어 디코드에는 소급해서 이득을 주지 못한다.

요약 조회 비용은 화면 해상도와 가시 복잡도에 맞추어 제한하는 것이 목표다. 광역뷰의 인스턴스
열거는 금지하되, 레이어 수·저장 평면 합성·트리 방문 비용까지 픽셀 수만으로 제한됐다고 주장하지 않는다.

MAIN01의 재현 조건을 성능 판정에 포함한다: detail medium, thin keep, full depth,
449개 중 paint 순서가 가장 위인 10개만 표시하고 fit 근처까지 축소한다. 사용자 로그는
22979 ms(load 3226 ms, 그 안의 plan 3200.8 ms, draw 4237 ms, publish 18.4 ms)이며
박스 200만 개, x8 coarser였다. 박스를 끄면 빨라지는 것이 확인됐지만 약 15.5초의 미계측
시간이 어느 단계인지는 아직 확인되지 않았다. 기존 박스 끔 프레임을 기준으로 전체 시간,
요약 조회 시간·방문 수·중간 메모리·출력 점 수를 함께 비교한다. 최종 점 수만 줄이고
그 전에 수백만 박스나 인스턴스를 열거하는 방식은 이 문제를 해결하지 못한다.

## 7. 이번 시각 실험과 다음 단계

`tools/mock_cut_density.py`는 25×34개의 분리된 얇은 사각형을 사용한다.
모든 도형이 밀도 대상인 작은 오라클이며, 실칩·현재 렌더러 출력이 아니다.

```
.venv/bin/python tools/mock_cut_density.py --compare --out /tmp/floe-cut-density-dither.png
```

- 위: 각 사각형에 최소 1픽셀을 주는 비교 모형.
- 아래: 배율에 따라 2×2씩 합쳐지는 공간 구역에 면적을 누적하고 양자화한다. 저밀도 보정은
  이 구역에서만 적용한다. 동일한 세계좌표 표본 순서를 사용한다.
- 점 위치는 원본에서 직접 생성하므로 빈 곳에 임의로 뿌리지 않는다.
- 기본 정수화는 고정 디더다. `--quantization round`는 종전 반올림 대조군,
  `--no-presence`는 존재 보정만 끔, `--seed N`은 고정 디더 seed다.
  `--compare`는 반올림/디더 × 보정 끔/켬의 네 조합을 출력한다.

**2026-09-21 리뷰 반영: 중간 배율의 밝아짐을 모두 저밀도 보정 탓으로 쓴 해석을 수정한다.**
50%에서 45구역 중 40구역의 질량은 약 1.505882 px², 나머지 5구역은 0.752941 px²다.
개별 반올림이 이를 모두 2 또는 1로 올려 64 px²를 85점으로 만든다. 보정을 꺼도 85점이다.

초기 칸 폭 8~16 px, 자격 문턱 1/256, 고정 seed 0의 재실행 결과는 아래와 같다.
디더는 `BLAKE2b(seed, 109/2, 레벨, gx, gy)`의 상위 53비트로 문턱을 정했다.
리뷰의 디더 표와는 해시 문턱이 다르므로 개별 합계를 일치시킨 값이 아니다.

| 배율 | 100% | 50% | 25% | 12.5% | 6.25% | 3.125% | 1.5625% |
|---|---:|---:|---:|---:|---:|---:|---:|
| 실제 면적 px² | 256 | 64 | 16 | 4 | 1 | 0.25 | 0.0625 |
| 반올림, 보정 없음 | 255 | 85 | 20 | 4 | 1 | 0 | 0 |
| 반올림 + 보정 | 255 | 85 | 23 | 8 | 2 | 1 | 1 |
| 고정 디더, 보정 없음 | 260 | 70 | 15 | 2 | 0 | 1 | 0 |
| 고정 디더 + 보정 | 260 | 72 | 18 | 6 | 2 | 1 | 1 |

표는 **픽셀 충돌 전 구역별 목표 점 수의 합**이다. 100%는 반올림·디더 모두 경계 구역의 점
1쌍이 같은 픽셀에 겹쳐 최종 254·259픽셀이 된다. 이전에 보고한 254점과 리뷰의 255점 차이는
이 계정 차이다. 도구는 `area_quota`, `presence_added`, `collisions`, 최종 `dots`를 분리한다.

디더는 특정 seed에서 면적을 정확히 맞추는 방식이 아니다. seed 0~255를 바꾼 별도 대조에서
50%의 보정 전 목표 점 수 평균은 **63.96875**(범위 55~72)로 면적 64에 가까웠다. seed를 매 프레임
바꾸자는 뜻이 아니며, 한 seed의 결과를 고르는 것과 통계적 편향 확인을 구분한다.
보정은 이 실험에서도 50%의 경계 구역에 2점을 더하므로 특정 전역 배율 이하에서만 작동하지 않는다.

보정 없는 디더는 6.25%의 0점이 3.125%에서 1점으로 다시 생기는 사례도 보였다. 고정 해시의
결정성만으로 줌 연속성이 보장되지 않는 구체적인 예다. 기본 보정 켬에서는 이 픽스처의 점 수
단조 감소와 공통 anchor를 확인했지만, 모든 뷰에 대한 포함 관계를 검증한 것은 아니다.
이 도구는 면적/공간 병합/정수화/보정의 대조 실험이다. 생산용 요약 조회, 연속 pan/줌 안정성,
일반 도형 합집합, 컷 경계 전환, 성능은 아직 검증하지 않는다.

후속 제안의 별도 검증 도구:

```
.venv/bin/python tools/check_cut_density_rules.py
```

- 같은 픽스처의 독립 디더에서 보정 끔은 **11/256 seed**가 어느 축소 단계에서 목표 점 수를
  다시 늘린다. 보정 켬은 이 픽스처에서 0/256이다. 총 점 수가 줄어도 앵커 집합이

- 공통 컷 오라클은 1/반/1/4옥타브 × 128개 요청 컷 × 4개 depth의 **1536조합**에서,

## 8. 1단계 결과: 선택 규칙과 매개변수 (2026-09-21)

- `round` 구역별 반올림, `dither` 레벨별 독립 디더(§2), `parent-min` §4.1의 부모 min 문턱,

  어느 쪽이든 그 존재 구역의 어떤 면적 구역도 점을 받지 못했을 때만, 구역당 많아야 1점이다.
- 점 배치: 순위 그대로(`pool[:N]`)와 **픽셀 인식**(현재 뷰에서 이미 켠 픽셀이면 다음 순위로).

pitch 8 px, τ = 1/256, seed 0. `lit` = 고유 픽셀 수 ÷ 면적(50 %~6.25 %의 평균; 충돌·존재 보정
포함 — 화면 밝기가 면적과 얼마나 맞는지), `pop-in` = 축소 한 단계에서 새로 나타난 앵커 수 합계.

| 픽스처 | round lit / pop-in | dither | parent-min | survivors | survivors k=2 픽셀 인식 |
|---|---|---|---|---|---|
| 배열 | 1.34 / 0 | 1.26 / 2 | 1.42 / 0 | 1.26 / 0 | **0.99 / 0** |
| 통로 | 0.89 / 0 | 0.90 / 0 | 1.01 / 0 | 0.90 / 0 | **1.00 / 0** |
| 가는 선 | 2.34 / 0 | 2.34 / 0 | 2.51 / 0 | 2.34 / 0 | **1.03 / 0** |
| 중복 | 1.34 / 0 | 1.26 / 2 | 1.42 / 0 | 1.26 / 0 | **0.99 / 0** |
| 불균등 | 0.77 / 0 | 0.87 / 5 | 0.82 / 0 | 0.77 / 0 | **0.97 / 0** |

seed 0~15의 반복(`--seeds 16`; 재등장·밝기 범위·마지막 점): `survivors k=2 픽셀 인식`은 **모든 seed·픽스처에서
재등장 0, 마지막 점 유지**, lit 범위 배열 0.84~1.18, 통로 0.99~1.02, 가는 선 0.76~1.27, 불균등
0.96~0.99(작은 질량의 디더 잡음 — 평균은 1 근처). `dither`는 배열 12/16, 불균등 16/16 seed에서
재등장했다. `parent-min`은 재등장 0이지만 lit가 불균등 0.54~1.03(형제 붕괴), 배열 1.26~1.80이다.
빈 통로의 점은 모든 규칙에서 0이다(점이 앵커에만 놓이므로). 중복 배치는 배열과 **모든 열이 같은**
결과다 — 합집합(8.415) 대신 면적 합(19.64)을 썼다면 2.3배 밝아진다.

무엇이 무엇을 해결했는가:

1. **포개짐 = `survivors`.** 부모가 자식이 보인 앵커 중에서만 고르므로 축소한 쪽의 앵커 집합이
   확대한 쪽의 부분집합이다(구성상; 존재 보정 점도 자식이 보인 앵커가 있으면 그중에서 고른다).
   점 수는 디더라 면적과 같은 기대값이고, `parent-min`처럼 성긴 형제가 밀집 형제를 끌어내리지 않는다.
   대가는 **부족분**(`short` 열): 부모의 디더 N이 자식들이 실제로 보인 점보다 많으면(자식들의 디더가
   모두 내림으로 떨어졌거나, k=2라 존재 점이 적게 생겨서) 모자란 만큼 덜 그린다 — 픽셀 인식에서는
   후보 픽셀이 모두 찼을 때도. 줌 7단계 전체 합으로 seed 0에서 불균등 5, 가는 선 5, 통로 2, seed
   0~15의 최대 7점이다. 점은 늘 **적게** 틀리고(재등장·증가는 만들지 않는다), 위 lit 범위에 이미
   들어 있다.
2. **존재 보정의 구역 = 면적 구역의 4×4.** 면적 구역마다(`k=0`) 보정하면 균일하게 성긴 내용 —
   가는 선 — 에서 면적 규칙이 0을 준 **모든 구역에 한 점씩** 붙어 2.34배 밝아진다(280점 추가). §2의
   "보정은 칸당 최대 1/64"는 맞지만, 실제 밀도가 τ와 1/64 사이인 내용은 전부 1/64로 올라간다는 뜻이다.
   `k=2`(32~64 px 구역)면 1.03배이고 마지막 점은 그대로 남는다.
3. **밀집 영역의 밝기 = 픽셀 인식 배치.** 순위만으로 N개를 고르면 한 픽셀에 앵커가 여럿 걸려 밀집한
   곳이 10~23 % 어두워진다(통로 픽스처 충돌 1303). 이미 켠 픽셀을 건너뛰면 충돌 0, lit 1.00이다.
   고르는 대상이 여전히 생존자이므로 포개짐은 깨지지 않는다.
4. **pitch 8 대 16**: 규칙적인 배열은 16이 잡음이 작고(구역당 질량이 커서), 군집·불균등은 8이 낫다.
   8에서 k=2·픽셀 인식을 쓰면 다섯 픽스처 모두 lit 0.97~1.03이라 **8을 기본**으로 한다.

**결정(2단계 이후의 기본안).** 규칙 `survivors`(디더 N, 자식 생존자 중 순위 선택), 면적 구역 8~16 px,
존재 보정 4×4 면적 구역·τ = 1/256·많아야 1점, 픽셀 인식 배치. 모두 이 작은 오라클에서의 결정이며
실칩에서 다시 확인한다.

2단계로 넘기는 문제(이 실험이 드러낸 것):

- **생존자 사슬은 인덱스 시점, 픽셀 인식은 렌더 시점이다.** 인덱스는 뷰의 픽셀 격자를 모르므로 사슬을
  픽셀 건너뛰기 **없이** 만들고(구역·레벨마다 자식 생존자의 순위 순 목록 — 부모 N의 약 4배라 건너뛸
  여유가 있다), 렌더러가 그 목록에서 현재 뷰의 빈 픽셀로 N개를 고른다. 그러면 가는 뷰가 건너뛴 후보를
  굵은 뷰가 보일 수 있다. 오라클의 `survivors k=2 px-aware index`가 이 분리를 그대로 재면: 재등장이
  통로·불균등에서 seed 16개 중 2개, 줌 7단계 전체에서 많아야 1점이고 lit·부족분은 뷰 순서 사슬과 같다
  (배열·가는 선·중복은 0). 포개짐은 이 정도의 근사로 받아들인다. 목록의 길이가 저장량을 정한다 —
  가장 가는 레벨의 점 수 × 4/3(피라미드) 규모이고, 가장 가는 레벨은 "그 크기대가 컷 경계에 닿는
  배율"이다.
- 앵커 생성 규칙(도형 안의 고정 세계 격자, 가는 도형은 중심선)이 인덱서와 오라클에서 같아야 한다.
- 이 오라클은 한 레이어·2D 사각형만 다룬다. 회전·반사·배열 반복·depth·겹치는(중복이 아닌) 도형의
  합집합은 2단계의 작은 합성 파일에서 확인한다.

## 9. 2단계 결과: 공동 누적 평면, 공통 양자화 컷, 저장량 (2026-09-21)

`tools/density_planes_experiment.py`(인덱스·렌더러·파일 형식 아님). 메모리 안에 만든 **작은 계층
합성 레이아웃** — 셀·배열·회전·반사, 같은 블록의 정확한 중복 배치, depth 4의 작은 도형 위를 덮는
depth 0의 큰 도형, 폭 256의 십자형 빈 통로 — 을 펼친 21,384개 사각형(depth 0~4, 3은 비어 있음,
작은 변 1~600 DBU)에서, 1 DBU = 1 픽셀 래스터로 모든 합집합 면적을 **정확히** 잰다. 뷰는 6옥타브를
옥타브당 16단계로 훑고(medium 3 px, `c_req = ceil(3 / s)` DBU — renderd와 같다), 구역은 1단계대로
8~16 px에 투영되는 레벨이다. 크기 경계표는 정수 DBU, 1/4옥타브와 1/2옥타브.

```sh
.venv/bin/python tools/density_planes_experiment.py      # 약 1분, 최대 메모리 약 0.5 GB
```

**검사(모두 통과).** F는 컷과 depth 양쪽으로 단조다(95컷 × 5 depth × 7레벨). 97뷰 ×
경계표 2 × depth 2(전체·1)의 388가지 모두에서 `원본(작은 변 >= c_eff) ∪ F[c_eff, d]`가 그 depth의
레이아웃과 **픽셀까지 같다**. 통로 안의 구역은 모든 레벨에서 0이고, 중복 배치는 합집합에 0을
더한다(면적 합에는 +27,700).

**공동 조건이 필요한 이유(§6.3의 확인).** 크기 누적 평면과 depth 누적 평면을 따로 두고
`min(F_size[k], F_depth[d])`로 합치면, depth 0의 큰 도형 아래 depth 4의 작은 도형이 있는 구역이
F[k,0] = 0인데 **가득 참(+1.000)**으로 읽힌다 — 빈 곳에 켜지는 구역이 한 평면의 최대 9.7 %(L3),
31.2 %(L9, 16구역 중 5개)다.
크기대를 따로 저장해 더하면 전체 +2.2 %, 한 구역 최대 +37.5 %다(배열 위의 레일, 채움 위의 배선).
공동 누적 평면 F[k,d]를 기본으로 유지한다.

**공통 양자화 컷의 품질과 원본 비용.** 밝기 = (원본이 켠 픽셀 + 원본이 켜지 않은 곳의 밀도 면적) ÷
실제 면적. 원본은 닿는 픽셀을 모두 켜는 규칙이다.

| 컷 | 밝기 범위 | 가장 큰 한 단계 변화 | 2 % 넘는 단계 | 원본 도형 수(연속 대비) 평균 / 최대 | 원본 픽셀 칠 평균 / 최대 |
|---|---|---:|---:|---|---|
| 연속(현재) | 1.000~1.156 | 12.4 % | 17 | 1 | 1 |
| 1/4옥타브 | 1.000~1.156 | 12.4 % | 17 | +2.1 % / 3개 대 1개 | +0.2 % / +16 % |
| 1/2옥타브 | 1.000~1.199 | 15.4 % | 19 | ×8.4 / 12,847개 대 303개 | +6 % / +85 % |

- 밝기의 계단은 **연속 컷에도 같은 크기로 있다.** 한 크기대(예: 4 DBU 비아 12,544개)가 원본에서
  밀도로 넘어가는 순간이며, 컷 근처의 원본은 닿는 픽셀 규칙으로 부풀어(3 px 안팎의 비아가 한 변에
  3~4 px) 면적보다 밝다. §5의 컷 경계 밝기 문제이지 양자화의 문제가 아니다. 1/4옥타브는 연속과 같은 값이고,
  1/2옥타브는 더 작은 픽셀 크기까지 원본으로 남겨 최대 1.199로 밝아진다.
- 원본 비용은 **`[c_eff, c_req)` 크기대에 도형이 몇 개 있는가**로만 정해진다. 1/2옥타브 최악은
  `c_req = 5`에서 `c_eff = 4`라 비아 12,544개가 원본에 남은 단계다.

같은 질문을 **실제 렌더러**로: 합성 칩 `main01_chip_p10`, 1920×1080, thin keep, full depth, 박스 끔,
`cut = 3`(현재) / `2.53`(1/4옥타브의 최악) / `2.13`(1/2옥타브의 최악) px. 새 워커의 첫 프레임(cold)과
두 번째(warm), 컷 순서를 돌려 2회. cold는 첫 실행의 OS 캐시 영향이 커서 warm과 작업량을 본다.

1/4옥타브의 **최악**(모든 뷰가 2.53 px로 떨어지는 것은 아니다)에서 warm +6~10 %, 칠한 멤버 최대 +77 %다.
1/2옥타브는 +30 %와 +87~206 %라 기각한다. 합성 칩의 크기 분포가 실칩과 같다는 보장은 없으므로 실칩의
같은 비교는 4단계에서 한다.

**저장량.**

- **한 레벨은 한 옥타브의 컷만 묻는다.** 구역 z가 8~16 px로 투영되는 배율에서 `c_req`는
  `(3z/16, 3z/8]`이다. 그래서 레벨마다 필요한 크기 평면은 1/4옥타브에서 4~5개(측정 `{3:1, 4:3, 5:4,
  6:4, 7:5, 8:5, 9:5}`), 1/2옥타브에서 2~3개뿐이다 — 경계표 40개 전부가 아니다. §6.3의 `B`는 **레벨당
  1/h개**로 바뀐다. detail 세 단계(5/3/1 px)를 모두 두면 `(5z/16, 5z/8]`, `(3z/16, 3z/8]`,
  `(z/16, z/8]`의 합 약 2.7옥타브, 1/4옥타브로 레벨당 11~12개다.
- 작은 파일에서 비어 있지 않은 구역은 9.1 %, 16×16구역 타일 1,135개 중 795개(70 %)가 depth 또는 크기로
  바로 아래 평면과 **같아서 공유**된다(비어 있는 depth 3, 그 타일에 새 도형을 더하지 않는 크기대).
- **8비트 선형 값은 존재를 지운다.** 비어 있지 않은 62,302구역 중 2,061개(3.3 %)가 0이 된다 — §2가
  지키려는 마지막 점이다. 16비트는 0개다. 첫 파일은 16비트로 한다(8비트에 "0이 아니면 최소 1"을 쓰면
  τ가 사실상 1/255로 올라간다).
- **top 공간에 평탄화한 조밀 평면**의 크기(합성 칩의 범위 18.2 × 18.7 mm, 1920×1080, fit 구역
  262 µm = 15 px, 449레이어 × 레벨당 4.5평면 × 2바이트, 피라미드 포함):

| 가장 가는 레벨 | 구역 | depth 평면 6개 | depth 평면 16개 | detail 3단계·depth 6개 |
|---|---:|---:|---:|---:|
| fit | 262 µm | 0.1 GB | 0.3 GB | 0.3 GB |
| fit ×4 | 66 µm | 2.5 GB | 6.8 GB | 6.8 GB |
| fit ×8 | 33 µm | 10 GB | 27 GB | 27 GB |
| fit ×16 | 16 µm | 41 GB | 110 GB | 110 GB |
| fit ×64 | 4 µm | 657 GB | 1753 GB | 1753 GB |

  한 옥타브마다 4배다. 빈 구역·공유 타일로 줄지만, 실칩의 넓은 구역은 대부분 비어 있지 않으므로 작은
  파일의 9 %를 그대로 옮기지 않는다. MAIN01의 실제 범위는 모르며 식은
  `S ≈ (4/3)(X/z_f)(Y/z_f) × 레이어 × 레벨당 평면 × D × 2바이트`다.
  → **top 공간 평면은 fit에서 몇 옥타브(×4~×8) 안쪽까지만 현실적이다.** 그보다 가까운 뷰는 §6.1의
  서브트리 요약 경로가 필요하다.

**만드는 방법: 정확한 합집합은 아래에서 위로 합성되지 않는다.** 모든 인스턴스를 top으로 펼쳐 칠하는
것은 OVO2가 비트로 하는 일이고 MAIN01에서 1시간을 넘었다. 자식 요약의 비율은 겹치는 부분을 모르므로
더할 수 없다. 합성 가능한 후보를 정확한 F와 비교했다(full depth, 레벨마다 가장 넓은 크기대):

| 레벨 | 도형 면적 합 | TOP 자식별 합집합의 합 | 비트 OR(구역/16) | min(자식 합, 비트) |
|---|---:|---:|---:|---:|
| L3 (c<3) | 1.063 (+0.375) | 1.063 (+0.328) | 1.000 (0) | 1.000 (0) |
| L5 (c<11) | 1.031 (+0.258) | 1.031 (+0.255) | 1.064 (+0.037) | 1.002 (+0.026) |
| L6 (c<23) | 1.060 (+0.292) | 1.058 (+0.280) | 3.002 (+0.572) | 1.041 (+0.251) |
| L9 (c<181) | 1.076 (+0.039) | 1.055 (+0.038) | 4.462 (+0.700) | 1.055 (+0.038) |

(전체 면적 비, 괄호는 한 구역의 최대 초과 — 구역 면적 대비.) 비트는 가는 선이 부분 칸을 통째로 채워
넓은 레벨에서 3~4.5배가 되고, 면적 합은 겹침을 두 번 센다. **둘의 min**은 1.000~1.055이며, 남은
오차는 이 레이아웃에서 TOP 자식끼리의 정확한 중복 블록이다. 합성 가능한 쌍(면적 합 + OR 비트)의
오차는 **같은 레이어에서 서로 다른 인스턴스가 겹치는 양**으로 제한되고, 실칩에 그것이 얼마나 있는지는
4단계의 측정 대상이다.

**결정(3단계의 기본안).** 1/4옥타브 정수 DBU 경계표, 16비트 F, 공동 누적 F[k,d], 레벨마다 그 레벨이
묻는 크기 평면만. 첫 연결은 **넓은 뷰(fit부터 ×4~×8까지)의 top 공간 평면**이다 — MAIN01의 검증
사례(마지막 10레이어, full depth, fit)가 여기에 든다. 그보다 가까운 뷰는 서브트리 요약이 생길 때까지
현재 경로(컷 아래 없음)를 유지한다.

3단계로 넘기는 문제:

- **앵커의 출처.** 1단계의 생존자 규칙은 도형 안의 고정 세계 앵커를 전제한다. top 공간 평면에서는
  OR 비트의 켜진 부분 칸이 "도형이 있는 곳"이므로 점을 그 칸에 둘 수 있다. 그러나 레벨마다 부분 칸이
  2배씩 커져 앵커가 레벨마다 달라지면 포개짐이 깨진다. 가장 가는 레벨의 부분 칸을 앵커로 하고 굵은
  레벨의 켜진 칸마다 그 대표(가장 낮은 순위의 가는 칸)를 인덱스가 저장하는 방식을 먼저 검토한다.
- **빌더의 위치.** 인덱스 시점(OVO2처럼 원본 파싱을 걷는 `floe-index` 단계, 별도 파일)이어야 한다.
  렌더 시점의 계산은 MAIN01에서 불가능하다. 생성 시간·최대 메모리·파일 크기를 합성 칩에서 먼저 잰다.
- depth 평면 수: MAIN01은 대부분의 도형이 depth 0~5라 그 위의 평면은 대부분 공유될 것으로 보이지만,
  표의 "depth 6개"는 가정이다.

**사용자 판정(2026-09-21): top 공간 평면안은 추가 저장량이 너무 커서 현실성이 없다.** 저장 자료만으로
점을 고르는 3a(앵커·겹침 비트 포함)는 착수 전에 중단했다. 대신 새 파일 없이 셀·페이지 단위 요약이 조회할
양을 §10에서 쟀다.

## 10. 셀·페이지 단위 요약: 조회량과 저장량 측정 (2026-09-21)

§9의 평면 대신 **작은 단위 요약**을 두는 안이 실제로 얼마를 조회해야 하는지, 새 파일을 만들지 않고 기존
인덱스로 쟀다. 요약 후보는 (셀, 레이어)마다 서브트리 덮임 값 하나(잘린 자식 배치는 화면에서 컷보다 작으므로
값 하나로 놓인다), 페이지마다 4×4 덮임 격자다. 크기 대역은 두지 않는다 — 구역의 밀도 점 수를
`F_all − (원본이 이미 칠한 비율)`로 정하면 원본 아래의 작은 도형은 어차피 보이지 않기 때문이다.

`floe-index plan --density-probe 1`(진단 전용; explain 행에 그 판정을 한 working-set 셀 `owner`를 기록하게
했다 — 제품 판정은 불변)이 계획의 size cut 판정을 **화면 안의 인스턴스 수**로 곱한다. 화면에 완전히 든
인스턴스는 한 번 계산한 합을 공유하고, 화면 가장자리의 인스턴스는 멤버별로 걷는다(축 정렬 배열은 인덱스
범위를 잘라 가장자리 멤버만). 가장자리 인스턴스는 판정 전체를 세므로 상한이다.

```sh
.venv/bin/python tools/probe_density_queries.py data/synthetic/main01_chip_p10.oas   # 끝에 "type this" 요약
```

조건: 합성 1/10 칩, 1920×1080, 중심, full depth, 일반 레이아웃의 thin keep 요청(shape cut 켬, 가는 페이지
유지 안 함, 박스·wash·대표점 끔, 프레임 끔), 마지막 10레이어 / 전 레이어.

**읽은 것.**

1. **저장량은 현실적이다.** (셀, 레이어) 값과 페이지 격자는 이 칩에서 7.1 MB다. MAIN01은 셀이 약 3.2배이고
   페이지 수는 모르지만, 수십 MB 규모로 본다(실측 필요).
2. **레이어가 적으면 조회도 적다.** 마지막 10레이어는 fit에서 잘린 페이지 174개, BVH째 잘린 노드 526개(그 아래
   레코드 9,924개)다. 배열을 닫힌 식으로 다루면 레코드 수만큼만 조회하면 된다.
3. **전 레이어의 넓은 뷰에서는 잘린 내용 대부분이 BVH째 잘린 서브트리 아래에 있다.** fit에서 노드 23.7만
   인스턴스 아래 배치 레코드 3억 1,545만(멤버 49.9억)이다. 오늘 fit이 빠른 이유가 이 가지치기인데, 밀도를 위해
   그 아래를 걸으면 박스와 같은 문제가 된다. 노드 단위 요약은 마스크 있는 노드만으로도 588 MB(MAIN01은 그
   몇 배)이고, fit에서 잘린 노드의 39 %는 마스크가 없는 작은 노드다.
4. **중간 배율(전 레이어 ×16)은 가지치기가 없고 잘린 페이지 인스턴스가 557만**이다. 지금 0.04 s인 프레임이
   프레임마다 수백만 번 요약을 찍게 된다.

즉 셀·페이지 요약은 저장량으로는 가능하고 레이어가 적은 뷰에는 충분하지만, 전 레이어 뷰에서는 조회 수가
프레임당 10⁵~10⁷이고 넓은 뷰는 노드 단위의 묶음이 필요하다. 이 수치는 합성 칩 것이며(합성 칩의 배치 구조가
실칩과 같다는 보장은 없다), 실칩에서 같은 계측을 돌려 확인해야 한다. 실칩 사용자는
끝의 `== type this ==` 줄만 옮기면 된다.
