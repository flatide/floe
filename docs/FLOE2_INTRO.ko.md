# floe2 소개

> 마스크·레이아웃 리뷰를 위한 고속 뷰어. Calibre DESIGNrev/MDPView/RVE로 하던
> 레이아웃 조회, DRC 결과 리뷰, jobdeck 리뷰, 화면 캡처를 **라이선스 서버·좌석
> 제한 없이, 폐쇄망 서버에서, 더 빠르게** 한다.
>
> 2026-09-16, floe2 0.12.134 기준. 개발 중인 제품이며 현재 범위는 §5에 있다.

## 1. 현장의 문제

**Calibre**
- 좌석 수가 정해진 유상 라이선스라 큐 대기가 길고, 리뷰 도중 체크아웃이 끊길
  위험이 있다.¹
- 화면 캡처를 자동화하려면 GUI 세션(`-gui`)과 Tcl/Tk 스크립트, 그리고 라이선스
  체크아웃이 필요해 배치 캡처의 환경 제약이 크다.¹

**KLayout**
- 파일 전체를 메모리에 읽어 들인 뒤에야 그리므로 수 GB급 OASIS는 열 때마다
  로딩을 기다린다.¹
- jobdeck(MEBES `.jb`)을 기본 기능으로는 열지 못한다.

## 2. 한눈에 보는 차이

| | Calibre | KLayout | floe2 |
|---|---|---|---|
| 라이선스 | 유상, 좌석 제한, 큐 대기¹ | 무료 | 라이선스 서버·좌석 제한 없음. 서버 자원이 허용하는 만큼 동시에 |
| 대용량 OASIS 오픈 | 열 때마다 로딩¹ | 열 때마다 전체 로딩¹ | plain OASIS를 1회 인덱스(GDS·gzip은 변환 후), 이후 즉시 오픈. 인덱스는 서버 사용자 전원이 공유 |
| 같은 파일 오픈·드로잉 완료 | 기준 | — | **5~10배 빠름**¹ |
| jobdeck 리뷰 | MDPView | 미지원(기본 기능) | `.jb` 직접 오픈, level/chip view. **2배 이상 빠름**¹ |
| DRC 결과 리뷰 | RVE | 마커 브라우저(ASCII .db 통째 로드) | 뷰어 내장. 1회 변환 후 즉시 오픈, 리뷰어별 waive·note, 룰 메타 |
| 캡처·자동화 | `-gui` + Tcl/Tk¹ | 스크립트 | CLI 한 줄. 스크립트·GUI 불필요, 좌석 점유 없음 |
| 배포 | 설치 + 라이선스 서버 | 설치 | tar 하나, 호스트에 설치 없음, 폐쇄망 |

¹ 현장 사용자 실측·경험(2026-09). 같은 파일·같은 서버에서 오픈 시간과 드로잉
완료 시간, jobdeck은 리뷰 한 사이클을 비교한 값이며 floe2는 1회 인덱스가 준비된
뒤의 값이다. 저장소에 자동 기록되는 실측(§4)은 KLayout 기반 비교 셸 대비이며
Calibre와는 비교하지 않았다.

## 3. 핵심 우위

### 3.1 오픈과 드로잉이 빠르다

- **인덱스는 한 번, 오픈은 즉시.** `floe2 index chip.oas`가 소스 옆에 숨김
  폴더(`.chip.oas.ice`)로 인덱스를 만든다(소스 폴더에 1회 쓰기 권한 필요,
  시간은 파일 크기에 비례하는 1회 비용).
  이후의 오픈은 화면과 교차하는 부분만 읽고, 같은 서버의 모든 사용자가 그
  인덱스를 복사·변환 없이 공유한다.
- **멀티코어 Rust 렌더러.** 읽기와 그리기가 병렬이다. GPU·OpenGL을 요구하지
  않는 CPU 렌더이고 화면은 일반 X11 이미지로 전송되므로 Exceed TurboX 같은
  원격 X 서버에서 동작한다.
- **광역 뷰는 점유 요약으로.** jobdeck의 광역 뷰는 원본 도형을 다시 읽지
  않고 인덱스 때 만든 점유 요약(4 µm 격자, 빈 공간 위치 보존)으로 그린다(덱의
  소스는 기본, 단독 마스크 레이아웃은 `floe2 index --occupancy`). 소스 600개
  이상인 실제 덱의 레티클 전면급 뷰가 depth와 무관하게 0.2초 안에 뜬다(§4).
- **공유 서버를 위한 메모리 정책.** 뷰어의 디코드 캐시는 호스트 RAM에 비례하지
  않는 기본 1 GB라(환경변수로 조정, 프로세스 전체 상한은 아님) 여러 사용자가
  동시에 띄워도 사용량이 예측 가능하다. 인덱싱은 별도의 1회 작업이다.

### 3.2 라이선스와 배포가 단순하다

- 라이선스 서버·키·좌석 제한이 없다. 한 서버에서 사용자 DISPLAY마다 창이
  뜨고, 같은 사용자는 창 하나에 파일을 넘겨 쓴다.
- 산출물은 tar 하나. Python·GTK·NumPy/Pillow·Rust 바이너리가 들어 있어 풀고
  `./floe2 view`를 실행하면 끝이며 호스트에 아무것도 설치하지 않는다.
  x86_64 리눅스(glibc 2.28, RHEL 8급 이상), X 디스플레이, 시스템 폰트만 있으면
  된다.
- 번들은 반입 전에 인터넷(또는 미러)이 되는 x86_64 리눅스 빌드 머신에서 만들고,
  폐쇄망에서는 tar만 반입해 풀고 실행한다. KLayout은 필요 없다.

### 3.3 DRC 리뷰가 편하다

- Calibre ASCII 결과 DB(`.db`)는 한 번 변환(pack)해 두면 원본 없이 즉시 열린다.
  95 MB DB 기준 매번 2.7초 파싱 대신 수십 ms(§4). 변환은 뷰어가 열 때 물어보고
  하거나 `floe-index drc results.db`로 한다.
- 브라우저는 뷰어 왼쪽에 상시 내장된다. 룰 목록(에러 수/waived 수, 이름 검색과
  유형 필터), 에러 번호 그리드, 에러 상세. 에러 번호는 Calibre RVE의 전역 번호와
  같아 리포트의 번호를 그대로 찾는다.
- 더블클릭하면 에러가 화면의 30%가 되도록 점프하고 CD 룰러가 자동으로 붙는다.
  `.`/`,`로 다음·이전 에러, **in view** 체크는 현재 화면 안의 위반만 목록에
  남긴다. 화면에서 박스로 에러를 골라 한꺼번에 waive한다.
- **waive와 note는 리뷰어별 파일**로 pack 옆에 자동 저장된다. 공유·읽기 전용
  pack도 각자 리뷰할 수 있고(결과 폴더에 쓰기 권한이 없으면 임시 폴더에
  기록되므로 save로 남긴다), 같은 DB를 다시 변환해도 기록이 유지된다. note
  입력에는 IME 없는 서버를 위한 내장 한글 조합기가 있다.
- SVRF 룰덱을 읽어 두면(실런과 같은 `-D` 스위치) 에러 상세에 제약 원문,
  측정값 대 한계값(Δ, %), 원천 레이어, derivation이 붙고, 점프 때 그 룰의 원천
  레이어만 켜 준다.
- GUI 없이도 된다. `floe2 drc db --rules/--errs`는 JSON을, `floe2 render --drc`는
  룰별 에러 스냅숏 PNG를 만든다. 스냅숏의 에러 도형·CD 룰러·라벨은 픽셀에
  굽지 않고 PNG 안 주석으로 실려, 이미지 주석 뷰어 flateyes(자매 도구)에서는
  편집 가능한 주석으로, 다른 도구에서는 평범한 PNG로 보인다.

### 3.4 jobdeck 리뷰가 빠르다

- MDPView가 여는 `.jb`를 `floe2 view deck.jb`로 바로 연다. 소스는 재작성·복사
  없이 각자의 인덱스를 런타임에 합성하므로 소스가 수백 개여도 인덱스는 소스당
  한 번뿐이고, 이미 인덱스된 소스는 건너뛴다. 로드할 level만 고르면 그 level이
  쓰는 소스만 인덱싱·로드한다(`--level 1,3`).
- 열 때 MDPView처럼 로드할 mask level을 먼저 고르고, **level view / chip view**를
  Ctrl+,로 즉시 전환한다. level view 색은 MDPView와 같은 열 가지 색 순환이다.
  floe2 확장으로 소스 LY/DT별 source layer view를 더했다.
- chip view는 level 아래 소스 칩 트리다. 부모를 끄면 하위가 모두 꺼지고, level
  view와 chip view를 오가도 숨긴 칩이 다시 나타나지 않는다(MDPView는 다시
  나타남, 현장 관찰).
- depth·detail·fit·goto·룰러·DRC 좌표 점프가 덱 좌표에서 그대로 동작한다.
  누락·미지원 소스가 있어도 덱은 열리고 그리지 못한 배치는 제목과 `floe2 info`에
  보고된다. `floe2 jobdeck deck.jb --report r.json`은 뷰어 없이 덱의 level·CHIP·
  배치 수와 identifier 불일치를 점검한다.
- 광역 뷰는 §3.1의 점유 요약으로 그린다.

### 3.5 캡처와 자동화가 한 줄이다

```sh
floe2 render chip.oas --bbox 5000,5000,5200,5200 --px 1200 --out a.png
floe2 render chip.oas --drc out.db --drc-rule M1.SPACE.1 --drc-err 1-50 --px 800 --out snap.png   # snap_1.png …
```

- GUI·스크립트 언어·라이선스 체크아웃 없이 CLI 한 줄로 찍는다. 영역은 bbox,
  기준점+크기(`--at 50mm,90mm --size 32mm,24mm`), 네 꼭짓점 mosaic(`--corners`)으로
  지정하고, `--batch`는 소스를 한 번 열고 여러 장을 찍으며 `--report`로 각 장의
  영역·시간을 JSON에 남긴다. 레이아웃과 덱 모두 같다.
- 기본은 도형을 하나도 생략하지 않는 보관용 렌더이고, `--detail low/medium/high`를
  주면 뷰어 화면과 같은 수준으로 작은 도형을 생략해 뷰어에서 본 그대로 찍는다.
  캡처가 불완전하면 exit 3으로 알린다.
- `floe2 clip chip.oas --bbox … --out region.oas`는 관심 영역만 별도 OASIS로 잘라
  낸다. 수십 GB 원본 대신 문제 영역만 주고받는다.
- `floe2 view chip.oas --goto X,Y,W`는 이미 떠 있는 창에 전달되어 그 좌표로
  점프한다. 리포트나 스크립트의 좌표 링크 한 번으로 뷰어를 연다. 뷰어에서는
  Ctrl+C가 현재 화면(룰러·라벨 포함)을 클립보드에 복사한다.

### 3.6 Calibre 사용자에게 익숙하다

- 마우스·키 조작이 DESIGNrev와 같아 재교육 없이 쓴다. 우드래그 영역 줌, 좌클릭
  pick, 좌/중드래그 팬, depth(숫자 키 0~9), `g` 좌표 이동(리포트의 "x, y"를
  그대로 붙여넣기), Ctrl+Z/Shift+Z/Ctrl+A 줌, 다중 룰러.
- 레이어 패널은 Calibre 스타일이다. MDPView가 쓰는 `.layerprops`(색·채움·표시·
  선폭)를 자동으로 읽고 같은 형식으로 내보낸다. 소스 옆에 두면 같은 서버의 모든
  사용자가 같은 색·채움으로 본다. 팔레트는 Calibre와 같은 7 × 7 색 이름 표와
  같은 이름의 채움 패턴 20종으로 호환된다.
- pick은 클릭 지점을 포함하는 가장 작은 도형을 고르고, 같은 지점을 다시 누르면
  겹친 도형을 순환한다. 룰러는 도형의 꼭짓점·엣지에 정확히 스냅한다.

## 4. 근거: 정확도와 실측

**정확도**
- 렌더 결과는 같은 OASIS를 KLayout으로 직접 그린 화면과 13개 뷰·14개 스타일
  검사로 자동 대조된다(경계 1 px 밴드 안의 차이만 허용, 성분 소멸 금지).
  jobdeck 합성 프레임은 평탄화한 단일 레이아웃을 그린 프레임과 바이트 동일하다.
- 워커 수·타일 크기와 무관하게 같은 요청은 같은 PNG를 만든다. 메모리 예산을
  넘는 뷰는 빈 화면을 정상처럼 내지 않는다. 단일 레이아웃은 명시적으로 알리고,
  jobdeck은 예산 안에서 나눠 그려 완전한 프레임을 만든다.
- 광역 뷰의 점유 요약은 실제 도형과 1 px 이내에서 일치하고 3 px 이상의 빈 틈은
  항상 보인다(2 px 이하 틈은 닫혀 보일 수 있다). 확대하면 원본 도형으로 돌아온다.

**실측 (저장소 기록)**

같은 서버·같은 실칩에서 잰 값이다. 비교 대상은 당사가 개발 검증용으로 유지하는
KLayout(Python API 0.30.9) 기반 비교 셸로, 같은 인덱스로 필요한 부분만 KLayout에
넣어 오프스크린으로 그린다. 스톡 KLayout GUI(파일 전체 로딩)보다 유리한 조건이며
Calibre와는 비교하지 않았다. 실칩·실제 덱 수치는 현장 서버에서 잰 시간만 기록했고
데이터는 반출하지 않았다.

| 실칩 뷰 (첫 방문, 캐시 없음) | KLayout 기반 비교 셸 | floe2 | 배수 |
|---|---|---|---|
| 심층 줌 (2 µm 창, 전체 계층) | 1.05초 | 0.15초 | 7.0 |
| 중간 줌 (100 µm 창, 전체 계층, 프레임 on) | 6.2초 | 0.96초 | 6.5 |
| 중간 줌 (100 µm 창, depth 3, 프레임 off) | 4.6초 | 0.83초 | 5.5 |

| 실제 덱 (소스 600개 이상), floe2 자체 전후 | 이전 | 이후 |
|---|---|---|
| 레티클 전면급 광역 뷰 (약 150 × 100 mm) | 16.7초 | 0.15초 (점유 요약, depth 무관) |
| 덱 전체 색인 (요약 포함), 1회 | — | 약 40분 |
| 덱 전체 점유 요약만 재생성 (`--jobs 48`), 1회 | — | 9.9분, 172 MB |

| DRC (합성 95 MB DB, 룰 1,000개) | 값 |
|---|---|
| ASCII 전체 파스 | 2.7초 |
| pack 변환 (8코어) | 0.2~0.34초, 21 MB (원본의 1/4.5) |
| pack 오픈 | 수십 ms |
| 공간 쿼리 (25만 에러 룰) | 다이 전체 6 ms, 100 µm 창 104 ms |

## 5. 현재 범위

- 소스는 plain OASIS만 읽는다. GDS와 gzip은 덱에서 `unsupported`로 건너뛰므로
  미리 OASIS로 변환한다. 확대·축소 배율이나 90° 단위가 아닌 회전이 든 셀 배치는
  열지 않고 오류로 알린다.
- 인덱스는 소스 옆에만 만들어져 소스 폴더에 쓰기 권한이 필요하다. 읽기 전용
  소스 폴더용 별도 인덱스 위치는 아직 없다.
- jobdeck에서는 pick/snap/clip과 라벨이 아직 동작하지 않는다. 배치별 회전·미러는
  포맷 미확정으로 미지원이며, chip view 색이 Calibre와 완전히 같은지는 검증
  전이다. 점유 요약으로 그린 광역 뷰에서는 그 레이어를 pick/snap할 수 없다.
- DRC: Calibre 자체의 waived 표기는 아직 읽지 않아 모든 에러가 Not Waived로
  시작한다. 100 GB급 실DB의 pack 변환 시간·크기는 실측 대기다.
- 뷰어 UI 문구는 영어다(일부 X 서버에 한글 글리프가 없음). 대상 환경은 x86_64
  리눅스이며 macOS는 개발용이다.

## 6. 시작하기

```sh
tar xzf floe2-portable-<ver>-<date>.tar.gz && cd floe2-portable
./selfcheck                       # 런타임 자가 점검 (창 없이)
./floe2 index chip.oas            # 1회: 소스 옆 숨김 폴더 .chip.oas.ice (마스크 레이아웃은 --occupancy 추가)
./floe2 view  chip.oas            # 오픈. 인덱스가 없으면 뷰어가 먼저 묻고 만든다
./floe2 view  chip.oas --drc out.db   # DRC 결과와 함께 (pack이 없으면 묻고 만든다)
./floe2 view  deck.jb             # jobdeck. 로드할 level을 고르고 연다 (소스 인덱스는 점유 요약 포함)
```

자세한 규격은 `docs/DRC.ko.md`, `docs/JOBDECK.ko.md`, `docs/SPEC-VIEWER.ko.md`,
설치는 `README.md`의 "폐쇄망 리눅스 배포" 절에 있다.
