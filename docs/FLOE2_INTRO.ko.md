# floe2 소개

> 마스크·레이아웃 리뷰용 고속 뷰어. Calibre DESIGNrev/MDPView/RVE로 하던
> 레이아웃 보기, DRC 결과 리뷰, jobdeck 리뷰, 화면 캡처를 **라이선스 서버나
> 동시 사용자 수 제한 없이, 폐쇄망 서버에서, 더 빠르게** 한다.
>
> 2026-09-16, floe2 0.12.140 기준. 개발 중인 제품이며 현재 지원 범위는 §5에 있다.

## 1. 현장의 문제

**Calibre**
- 동시 사용자 수가 정해진 유상 라이선스라 라이선스가 빌 때까지 기다리는 일이
  잦고, 리뷰 도중 라이선스를 잃을 수도 있다.¹
- 화면 캡처를 자동화하려면 GUI 세션(`-gui`)과 Tcl/Tk 스크립트, 그리고 라이선스
  체크아웃이 필요해 배치 캡처를 돌릴 환경을 갖추기가 번거롭다.¹

**KLayout**
- 파일 전체를 메모리에 올린 뒤에야 그리기 시작하므로 수 GB짜리 OASIS는 열 때마다
  한참 기다린다.¹
- jobdeck(MEBES `.jb`)을 기본 기능만으로는 열지 못한다.

## 2. 한눈에 보는 차이

| | Calibre | KLayout | floe2 |
|---|---|---|---|
| 라이선스 | 유상, 동시 사용자 수 제한, 라이선스 대기¹ | 무료 | 라이선스 서버·사용자 수 제한 없음. 서버 자원이 허용하는 만큼 동시 사용 |
| 대용량 OASIS 열기 | 열 때마다 로딩¹ | 열 때마다 전체 로딩¹ | plain OASIS는 인덱스를 한 번 만들면(GDS·gzip은 변환 후) 이후 바로 열림. 인덱스는 서버 사용자 전원이 공유 |
| 같은 파일을 열어 다 그릴 때까지 | 기준 | — | **5~10배 빠름**¹ |
| jobdeck 리뷰 | MDPView | 미지원(기본 기능) | `.jb`를 직접 열고 level/chip view 지원. **2배 이상 빠름**¹ |
| DRC 결과 리뷰 | RVE | 마커 브라우저(ASCII .db 통째로 로드) | 뷰어에 내장. 한 번 변환하면 바로 열리고, 리뷰어별 waive·note, 룰 메타데이터 표시 |
| 캡처·자동화 | `-gui` + Tcl/Tk¹ | 스크립트 | CLI 한 줄. 스크립트·GUI 불필요, 라이선스 점유 없음 |
| 배포 | 설치 + 라이선스 서버 | 설치 | tar 파일 하나. 호스트에 설치 없음, 폐쇄망 동작 |

¹ 현장 사용자의 실측과 경험(2026-09). 같은 파일·같은 서버에서 여는 시간과 화면이
다 그려지는 시간을, jobdeck은 리뷰 한 사이클을 비교한 값이며 floe2는 인덱스가 이미
만들어진 뒤의 값이다. 저장소에 자동 기록되는 실측(§4)은 KLayout 기반 비교 셸
대비이고, Calibre DESIGNrev와의 직접 비교는 §4의 현장 실측(2026-09-18)에 있다.

## 3. 핵심 우위

### 3.1 열기와 그리기가 빠르다

- **인덱스는 한 번, 열기는 바로.** `floe2 index chip.oas`가 소스 옆 숨김
  폴더(`.chip.oas.ice`)에 인덱스를 만든다(소스 폴더에 한 번 쓰기 권한이 필요하고,
  시간은 파일 크기에 비례하는 1회 비용이다).
  이후에는 열 때 화면에 걸리는 부분만 읽고, 같은 서버의 모든 사용자가 그 인덱스를
  복사나 변환 없이 함께 쓴다.
- **멀티코어 Rust 렌더러.** 읽기와 그리기를 병렬로 처리한다. GPU·OpenGL이 필요
  없는 CPU 렌더링이고 화면은 일반 X11 이미지로 전송되므로 Exceed TurboX 같은
  원격 X 서버에서도 동작한다.
- **광역 뷰는 점유 요약으로 그린다.** jobdeck의 광역 뷰는 원본 도형을 다시 읽지
  않고 인덱스 때 만든 점유 요약(칩 크기에 맞춘 격자, 큰 칩은 4 µm 셀; 빈 공간의
  위치는 보존)으로 그린다. 덱의 소스는 기본으로 만들고, 단독 마스크 레이아웃은
  `floe2 index --occupancy`로 만든다. 소스가 600개 넘는 실제 덱에서 레티클 전체
  크기의 뷰가 depth와 무관하게 0.2초 안에 뜬다(§4).
- **공유 서버를 고려한 메모리 정책.** 뷰어의 디코드 캐시는 호스트 RAM 크기와
  무관하게 기본 1 GB라(환경변수로 조정 가능, 프로세스 전체 상한은 아님) 여러
  사용자가 동시에 띄워도 사용량을 예측할 수 있다. 인덱싱은 별도의 1회 작업이다.

### 3.2 라이선스와 배포가 단순하다

- 라이선스 서버도, 라이선스 키도, 동시 사용자 수 제한도 없다. 한 서버에서
  사용자(DISPLAY)마다 창이 따로 뜨고, 같은 사용자가 파일을 더 열면 이미 뜬 창으로
  전달된다.
- 배포물은 tar 파일 하나다. Python·GTK·NumPy/Pillow·Rust 바이너리가 모두 들어
  있어 압축을 풀고 `./floe2 view`를 실행하면 되며, 호스트에는 아무것도 설치하지
  않는다. x86_64 리눅스(glibc 2.28, RHEL 8급 이상), X 디스플레이, 시스템 폰트만
  있으면 된다.
- 배포 파일은 인터넷(또는 미러)에 연결된 x86_64 리눅스 빌드 머신에서 만들고,
  폐쇄망에는 tar만 반입해 풀고 실행한다. KLayout은 필요 없다.

### 3.3 DRC 리뷰가 편하다

- Calibre ASCII 결과 DB(`.db`)는 한 번 변환(pack)해 두면 원본 없이 바로 열린다.
  95 MB DB 기준으로 매번 2.7초 걸리던 파싱이 수십 ms가 된다(§4). 변환은 뷰어가
  열 때 물어보고 하거나 `floe-index drc results.db`로 한다.
- DRC 패널은 뷰어 왼쪽에 항상 붙어 있다. 룰 목록(에러 수와 waived 수, 이름 검색과
  유형 필터), 에러 번호 표, 에러 상세로 구성된다. 에러 번호는 Calibre RVE의 전역
  번호와 같아 리포트에 적힌 번호를 그대로 찾을 수 있다.
- 에러를 더블클릭하면 그 에러가 화면의 30%를 차지하는 배율로 이동하고 CD 측정
  룰러가 자동으로 표시된다. `.`/`,`로 다음·이전 에러로 넘어가고, **in view**를
  켜면 현재 화면 안의 위반만 목록에 남는다. 화면에서 영역을 드래그해 여러 에러를
  한꺼번에 waive할 수 있다.
- **waive와 note는 리뷰어별 파일**로 pack 옆에 자동 저장된다. 공유하거나 읽기
  전용인 pack도 각자 리뷰할 수 있고(결과 폴더에 쓰기 권한이 없으면 임시 폴더에
  기록되므로 save로 남긴다), 같은 DB를 다시 변환해도 기록이 유지된다. note 입력에는
  한글 입력기가 없는 서버에서도 쓸 수 있는 내장 한글 조합 기능이 있다.
- SVRF 룰덱을 읽어 두면(실제 Calibre 런과 같은 `-D` 스위치 사용) 에러 상세에 제약
  원문, 측정값과 한계값의 차이(Δ, %), 입력 레이어, 레이어 유도식(derivation)이
  붙고, 에러로 이동할 때 그 룰의 입력 레이어만 켜 준다.
- GUI 없이도 쓸 수 있다. `floe2 drc db --rules/--errs`는 JSON을, `floe2 render --drc`는
  룰별 에러 스냅샷 PNG를 만든다. 스냅샷의 에러 도형·CD 룰러·라벨은 픽셀에 새기지
  않고 PNG 안에 주석으로 담기므로, 함께 제공하는 이미지 주석 뷰어 flateyes에서는
  편집할 수 있는 주석으로 보이고 다른 도구에서는 평범한 PNG로 보인다.

### 3.4 jobdeck 리뷰가 빠르다

- MDPView가 여는 `.jb`를 `floe2 view deck.jb`로 바로 연다. 소스 파일을 고쳐 쓰거나
  복사하지 않고 각 소스의 인덱스를 실행 시점에 합성하므로, 소스가 수백 개여도
  인덱스는 소스당 한 번뿐이고 이미 인덱스된 소스는 건너뛴다. 로드할 level만
  고르면 그 level이 쓰는 소스만 인덱싱하고 로드한다(`--level 1,3`).
- 열 때 MDPView처럼 로드할 mask level을 먼저 고르고, **level view / chip view**를
  Ctrl+,로 바로 전환한다. level view의 색은 MDPView와 같은 열 가지 색을 순환한다.
  floe2에서는 소스의 LY/DT별로 보는 source layer view를 더했다.
- chip view는 level 아래에 소스 칩을 트리로 보여 준다. 부모를 끄면 하위가 모두
  꺼지고, level view와 chip view를 오가도 숨긴 칩이 다시 나타나지 않는다(MDPView는
  다시 나타난다, 현장 관찰).
- depth·detail·fit·goto·룰러·DRC 좌표 이동이 덱 좌표에서 그대로 동작한다.
  누락되거나 미지원인 소스가 있어도 덱은 열리고, 그리지 못한 배치는 창 제목과
  `floe2 info` 출력에 표시된다. `floe2 jobdeck deck.jb --report r.json`은 뷰어
  없이 덱의 level·CHIP·배치 수와 identifier 불일치를 점검한다.
- 광역 뷰는 §3.1의 점유 요약으로 그린다.

### 3.5 캡처와 자동화가 한 줄이다

```sh
floe2 render chip.oas --bbox 5000,5000,5200,5200 --px 1200 --out a.png
floe2 render chip.oas --drc out.db --drc-rule M1.SPACE.1 --drc-err 1-50 --px 800 --out snap.png   # snap_1.png …
```

- GUI·스크립트 언어·라이선스 체크아웃 없이 CLI 한 줄로 캡처한다. 영역은 bbox,
  기준점+크기(`--at 50mm,90mm --size 32mm,24mm`), 네 모서리 좌표의 mosaic(`--corners`)
  으로 지정한다. `--batch`는 소스를 한 번 열어 여러 장을 캡처하고 `--report`는 각
  장의 영역과 소요 시간을 JSON으로 남긴다. 레이아웃과 덱 모두 같은 방식이다.
- 기본은 도형을 하나도 생략하지 않는 기록 보관용 렌더링이고, `--detail low/medium/high`를
  주면 뷰어 화면과 같은 기준으로 작은 도형을 생략해 뷰어에서 본 그대로 캡처한다.
  캡처가 불완전하면 exit 3으로 알린다.
- `floe2 clip chip.oas --bbox … --out region.oas`는 관심 영역만 별도 OASIS로 잘라
  낸다. 수십 GB 원본 대신 문제 영역만 주고받을 수 있다.
- `floe2 view chip.oas --goto X,Y,W`는 이미 떠 있는 창으로 전달되어 그 좌표로
  이동한다. 리포트나 스크립트의 좌표 링크 한 번으로 뷰어를 열 수 있다. 뷰어에서는
  Ctrl+C가 현재 화면(룰러·라벨 포함)을 클립보드에 복사한다.

### 3.6 Calibre 사용자에게 익숙하다

- 마우스·키 조작이 DESIGNrev와 같아 따로 익힐 것이 없다. 오른쪽 드래그로 영역
  확대, 왼쪽 클릭으로 도형 선택(pick), 왼쪽/가운데 드래그로 이동, 숫자 키 0~9로
  depth, `g`로 좌표 이동(리포트의 "x, y"를 그대로 붙여넣기), Ctrl+Z/Shift+Z/Ctrl+A
  줌, 룰러 여러 개.
- 레이어 패널은 Calibre 방식이다. MDPView가 쓰는 `.layerprops`(색·채움·표시·
  선폭)를 자동으로 읽고 같은 형식으로 내보낸다. 소스 옆에 두면 같은 서버의 모든
  사용자가 같은 색과 채움으로 본다. 팔레트는 Calibre와 같은 7 × 7 색 이름 표와
  같은 이름의 채움 패턴 20종을 지원한다.
- pick은 클릭한 지점을 포함하는 가장 작은 도형을 고르고, 같은 지점을 다시 누르면
  겹친 도형을 차례로 고른다. 룰러는 도형의 꼭짓점과 변에 정확히 붙는다.

## 4. 근거: 정확도와 실측

**정확도**
- 렌더 결과는 같은 OASIS를 KLayout으로 직접 그린 화면과 13개 뷰·14개 스타일
  검사로 자동 대조한다(경계 1 px 띠 안의 차이만 허용하고, 도형이 사라지는 경우는
  허용하지 않는다). jobdeck 합성 프레임은 평탄화한 단일 레이아웃을 그린 프레임과
  바이트 단위로 같다.
- 워커 수·타일 크기와 무관하게 같은 요청은 같은 PNG를 만든다. 메모리 예산을
  넘는 뷰를 빈 화면인 채로 정상 결과처럼 내보내지 않는다. 단일 레이아웃에서는
  예산 초과를 알리고, jobdeck은 예산 안에서 나눠 그려 완전한 프레임을 만든다.
- 광역 뷰의 점유 요약은 실제 도형과 1 px 이내로 일치하고 3 px 이상의 빈 틈은
  항상 보인다(2 px 이하 틈은 닫혀 보일 수 있다). 요약은 계층 깊이별로 저장되므로
  depth를 제한해도 그 depth의 도형만 그린다. 확대하면 원본 도형으로 돌아온다.

**실측값 (저장소 기록)**

같은 서버·같은 실제 칩에서 잰 값이다. 비교 대상은 개발 검증용으로 유지하는
KLayout(Python API 0.30.9) 기반 비교 셸로, 같은 인덱스에서 필요한 부분만 KLayout에
넣어 오프스크린으로 그린다. 파일 전체를 로딩하는 일반 KLayout GUI보다 유리한
조건이다. Calibre DESIGNrev와의 직접 비교는 아래 현장 실측 표에 있다. 실제 칩과
실제 덱의 수치는 현장 서버에서 잰 시간만 기록했고 데이터는 반출하지 않았다.

| 실제 칩 (처음 여는 뷰, 캐시 없음) | KLayout 기반 비교 셸 | floe2 | 배수 |
|---|---|---|---|
| 고배율 (2 µm 창, 전체 계층) | 1.05초 | 0.15초 | 7.0 |
| 중간 배율 (100 µm 창, 전체 계층, 프레임 on) | 6.2초 | 0.96초 | 6.5 |
| 중간 배율 (100 µm 창, depth 3, 프레임 off) | 4.6초 | 0.83초 | 5.5 |

| 실제 덱 (소스 600개 이상), floe2 자체 전후 | 이전 | 이후 |
|---|---|---|
| 레티클 전체 크기의 광역 뷰 (약 150 × 100 mm) | 16.7초 | 0.15초 (점유 요약, depth 무관) |
| 덱 전체 인덱싱 (요약 포함), 1회 | — | 약 40분 |
| 덱 전체 점유 요약만 다시 생성 (`--jobs 48`), 1회 | — | 9.9분, 172 MB |

| DRC (합성 95 MB DB, 룰 1,000개) | 값 |
|---|---|
| ASCII 전체 파싱 | 2.7초 |
| pack 변환 (8코어) | 0.2~0.34초, 21 MB (원본의 1/4.5) |
| pack 열기 | 수십 ms |
| 공간 쿼리 (에러 25만 개 룰) | 다이 전체 6 ms, 100 µm 창 104 ms |

**Calibre DESIGNrev 대비 현장 실측 (2026-09-18)**

같은 폐쇄망 서버에서 같은 파일을 floe2와 Calibre DESIGNrev v2023.2_27.15로 번갈아
열어 잰 값이다. floe2는 인덱스를 미리 만들어 둔 뒤의 값이고 Calibre는 매번 파일
전체를 읽는다(LAYOUT MEMORY: MAIN09 3,053 MB, MAIN01 3,475 MB). 뷰포트는 floe2
1414 × 969, Calibre 1359 × 886. 측정 당시의 floe2 버전은 기록하지 않았다(대표 점
`design.ovr` 적용 전).

측정 순서: ① 파일 로딩(detail medium) → depth 99(full)로 전환 → 1000 → 100 → 10 µm
창으로 goto. ② 다시 로딩 → depth 99 → detail high로 전환 → 같은 goto. 시간은 각
조작 뒤 화면이 완성될 때까지다.

**주의 — 광역 뷰는 같은 그림이 아니다.** 이 시점의 floe2는 fit이나 1000 µm급 광역
뷰에서 컷 아래 도형의 밀도를 표현하지 않는다(Calibre는 서브픽셀 도형을 솎아 밀도로
보여 준다). 그만큼 floe2가 덜 그리므로 로딩·depth 전환·1000 µm 행(`*`)의 배수는
floe2에 유리하게 잡힌 값이다. 같은 밀도를 보여 주는 대표 점
([REPRESENTATIVES](REPRESENTATIVES.ko.md))을 넣는 중이며, 적용한 뒤 같은 순서로 다시
잰다. 100 µm·10 µm 창은 양쪽 모두 원본 도형을 그리므로 그대로 비교할 수 있다.

읽는 법:

- Calibre의 depth/detail 전환은 파일을 다시 읽는 비용(4 분대)이고 floe2는 플랜을
  다시 계산하는 비용(1 초 이하)이다. 이 행들은 밀도 표현이 들어와도 자릿수가 바뀌지
  않는다.
- MAIN01의 첫 로딩 76 초와 첫 100/10 µm(3.4/5.4 초)는 두 번째 세션(8 초, 2.3/0.67 초)
  과 차이가 커, 인덱스 직후 OS 페이지 캐시가 비어 있는 상태의 첫 읽기로 보인다.
  확정은 그 프레임의 perf 상태줄(plan/decode/draw, pages)로 한다.
- MAIN01 100 µm 창의 2.3~3.4 초는 floe2에서 가장 느린 조작이고 Calibre와의 격차도
  2 배 이하로 가장 좁다. 밀도 차이와 무관한 구간이라 다음 최적화 후보다.
- 인덱스 29 분은 1회 비용이고 같은 서버의 모든 사용자가 공유한다. Calibre로 3 분
  50 초씩 여덟 번 여는 시간에 해당한다.

## 5. 현재 범위

- 소스는 plain OASIS만 읽는다. GDS와 gzip은 덱에서 `unsupported`로 건너뛰므로
  미리 OASIS로 변환한다. 배율이 있거나 90° 단위가 아닌 회전이 있는 셀 배치는
  열지 않고 오류로 알린다.
- 인덱스는 소스 옆에만 만들어지므로 소스 폴더에 쓰기 권한이 필요하다. 읽기 전용
  소스 폴더를 위한 별도 인덱스 위치는 아직 없다.
- jobdeck에서는 pick/snap/clip과 라벨이 아직 동작하지 않는다. 배치별 회전·미러는
  포맷이 확정되지 않아 미지원이고, chip view의 색이 Calibre와 완전히 같은지는
  아직 검증하지 않았다. 점유 요약으로 그린 광역 뷰에서는 그 레이어를 pick/snap할
  수 없다.
- DRC: Calibre가 기록한 waived 표기는 아직 읽지 않아 모든 에러가 Not Waived로
  시작한다. 100 GB급 실제 DB의 pack 변환 시간과 크기는 아직 재지 않았다.
- 뷰어 UI 문구는 영어다(일부 X 서버에 한글 글꼴이 없다). 대상 환경은 x86_64
  리눅스이며 macOS는 개발용이다.

## 6. 시작하기

```sh
tar xzf floe2-portable-<ver>-<date>.tar.gz && cd floe2-portable
./selfcheck                       # 런타임 자가 점검 (창 없이)
./floe2 index chip.oas            # 1회: 소스 옆 숨김 폴더 .chip.oas.ice (마스크 레이아웃은 --occupancy 추가)
./floe2 view  chip.oas            # 열기. 인덱스가 없으면 뷰어가 먼저 묻고 만든다
./floe2 view  chip.oas --drc out.db   # DRC 결과와 함께 (pack이 없으면 묻고 만든다)
./floe2 view  deck.jb             # jobdeck. 로드할 level을 고르고 연다 (소스 인덱스는 점유 요약 포함)
```

자세한 규격은 `docs/DRC.ko.md`, `docs/JOBDECK.ko.md`, `docs/SPEC-VIEWER.ko.md`,
설치는 `README.md`의 "폐쇄망 리눅스 배포" 절에 있다.
