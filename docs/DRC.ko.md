# DRC 기능 개요 (Calibre 결과 리뷰 파이프라인)

개발 기간 2026-08-13 ~ 08-19. 목표: Calibre DRC 결과(.db, 사무실
실측 수백 MB~139GB)를 즉시 열고, Calibre RVE에 준하는 브라우징과
waive 리뷰를 floe 뷰어 안에서 끝내는 것.

이 문서는 **전체 그림과 사용법** 중심의 개요다. 규범(포맷 바이트
레이아웃·뷰어 동작 계약·게이트 정의)은 각 SPEC이 정본:
- 포맷: `SPEC-FORMATS.ko.md` (`.<db>.tray` pack, `<deck>.rules.json`)
- 뷰어 계약: `SPEC-VIEWER.ko.md` §8b (DRC 브라우저 대용량 규약)
- 검증: `SPEC-VALIDATION.ko.md` (D1~D7, R1~R4+R3b)

## 1. 파이프라인 한눈에

```
results.db (Calibre ASCII, 정본)          deck.cal (SVRF 룰덱)
      │  floe-index drc (rust, 병렬)            │  floe-index svrf
      ▼                                         ▼
.results.db.tray (자기완결 pack, 숨김)   deck.cal.rules.json (룰 메타)
      └───────────────┬─────────────────────────┘
                      ▼
        floe view chip.oas --drc results.db
        (브라우저 + 캔버스 오버레이 + waive 리뷰)
```

```sh
# 1회 변환 (뷰어 open .db…가 자동으로도 수행)
rust/target/release/floe-index drc results.db [--jobs N]
# 룰덱 메타 (새 덱은 --scan 먼저; 실런과 동일한 -D 세트 필수)
rust/target/release/floe-index svrf deck.cal --scan
rust/target/release/floe-index svrf deck.cal -D SWITCH...
# 실행
.venv/bin/python -m floe view chip.oas --drc results.db
```

**셸 스크립팅 표면**(2026-08-19): 룰 목록·에러 목록은 JSON,
스냅샷은 룰/에러 지정 PNG 렌더 — 리포트 자동화용. **캡처 상한이
있는 호출자(ProperTee 등)는 파일로 리다이렉션 후 json_parse.**
옵션·출력 스키마·엔드-투-엔드 예시는
[DRC-CLI.ko.md](DRC-CLI.ko.md)가 스크립팅 전용 레퍼런스.

```sh
# 룰 목록: [{"name","errors","waived"}, ...]
python -m floe drc results.db --rules > rules.json
# 한 룰의 에러 목록(스트리밍 배열):
#   [{"local","global","kind","status","bbox":[x0,y0,x1,y1 um]},...]
python -m floe drc results.db --errs M1.SPACE.1 > errs.json
# 에러 스냅샷 PNG (--drc-err N | A-B | all; cap 200은
# 'all'에만 적용 — 명시 범위는 전량 렌더):
# 에러가 프레임의 30%(--drc-frac)를 차지하게 정사각 렌더
# (뷰어의 렌더 서비스 경로 그대로 — detail/헤어라인/LOD/커버리지
# 동일, depth만 full; 상주 세션이라 에러당 수십 ms).
# 에러 도형·CD 룰러·길이 라벨은 픽셀에 굽지 않고 **flateyes
# embed(iTXt "flateyes" 청크, fe_embed 포맷)**로 PNG 안에 실림
# — flateyes로 열면 주석으로 표시·편집되고(ppu로 um 길이 자동
# 라벨), 다른 도구에선 평범한 PNG. 단일 엣지 CD 룰러는 뷰어와
# 동일하게 화면 법선 방향으로 14px 띄우되 flateyes 임베드에는
# 양 끝 연결 점선을 넣지 않음. note = "룰 #로컬(전역)".
# 서로 평행한 두 엣지의 최근접점이 대각선으로 떨어지는 경우에는
# 대각선 실제 거리와 그 수평·수직 성분 룰러를 모두 임베드함.
# 사각형은 rules.json의 오류 조건에 맞는 방향만 룰러로 표시하며,
# 양쪽이 해당하거나 방향을 판단할 수 없으면 양쪽 모두 표시함.
# --layers를 지정해도 룰러용 rules.json은 읽음.
# 폴리곤 에러: 상태색 2px 외곽(halo 없음) + 내부 solid 50%
# 반투명 fill(#RRGGBB80 — 캡처 가독성 사용자 확정 2026-08-21,
# speckle 패턴 시도 후 회귀). 256 꼭짓점 초과는 외곽만.
# 레이어가 좁혀진 캡처(svrf 격리 또는 --layers)는 켜진 레이어의
# 색+fill 스와치 legend도 임베드 — fill은 패턴 **이름**으로 실림
# ("box <색> speckle NAME l/d"; flateyes 1.16+가 같은
# fillpatterns.def 표를 내장, 우하단 표에 실제 패턴으로 표시).
# 파일당 `로컬# <TAB> 전역# <TAB> 경로` 한 줄 출력.
# rules.json 사이드카가 발견되면(뷰어와 같은 자동 탐색, 또는
# --drc-rules 지정) 그 룰의 원천 GDS 레이어만 켜고 렌더 —
# 뷰어 더블클릭 격리와 동일; --layers 명시가 우선
python -m floe render chip.oas --drc results.db \
    --drc-rule M1.SPACE.1 --drc-err 1-50 --px 800 --out snap.png
```

## 2. pack `.<db>.tray` (v2, 레이아웃 버전 4) — 유일한 인덱스 포맷

- **자기완결**: 변환 후 .db 불필요. 크기 실측 원본의 1/3~1/4.5.
- **좌표**: 파일순 64에러 블록 varint 델타 스트림. 레코드에 서수
  없음 — **에러 번호 = 전역 파일순 순번**(Calibre RVE 동일)이
  `err_start + 블록 내 위치 + 1`로 파생되고 룰별 나열은 자동
  오름차순. 정수 dbu 좌표 무손실.
- **공간 쿼리**: 에러당 4B qbox(체크 bbox 위 256×256 격자) + 블록
  bbox 테이블 → `query_rect` 스트리밍(청크 → 희소/밀집 하이브리드
  → 후보 블록만 디코드, cap 조기 종료). 뷰포트 쿼리 0.1~3ms.
  `waived=` 필터는 쿼리 내부 cap 이전 적용(후필터는 cap 뒤 매칭
  누락 — D6b).
- **waive 리뷰**: 에러당 1B `[status]`(0=none, 1=waived,
  2=reserved) — 파일 재작성 없이 pwrite 제자리 수정. 룰당 u32
  `[wcount]` 카운터를 set_status가 증분 유지 → 필터 카운트 O(1);
  필터 상태 n/p·페이지 점프는 룰당 4M-청크 카운트 캐시로 최대 한
  청크만 스캔.
- **waive 저장 = 사용자별 자동 저장 + 명시적 save/load**
  (2026-08-28, D7/D9): 작업 상태는 pack **옆의** 리뷰어별 임시
  dotfile `.<db명>.waive.<리뷰어태그>`에 자동 기록 — 서버에서
  floe를 실행해 화면만 사용자 DISPLAY로 보내는 운용에서는 홈
  접근이 보장되지 않으므로, 모든 리뷰어가 닿는 결과 폴더가 저장
  위치다. **리뷰어 태그**: 공유 서버 계정이라 계정명은 유일하지
  않음 → `--floe-reviewer NAME` 파라미터(view/drc/render, 런처
  스크립트용 명시 지정 — `FLOE_REVIEWER` 환경변수도 유지) >
  DISPLAY 호스트부(직결 X, `ws-kim:0` → `ws-kim`; localhost류
  포워딩 번호는 로그인마다 바뀌므로 무시) > SSH 접속원
  IP(`SSH_CONNECTION` — 포워딩이어도 자리 머신 IP는 안정) >
  계정명(단일 사용자 환경) 순으로 안정 신호를 채택.
  pack은 다시는 쓰지 않으므로 **공유/읽기 전용 pack도 사용자마다
  독립 리뷰** 가능. **영속 기록은 명시적**: DRC 메뉴 `save waives
  as…`/`load waives…`가 같은 포맷의 스냅숏 저장/불러오기(리뷰
  공유·라운드 기록용) — load는 전체 대체(내 리뷰는 먼저 save)이고
  다른 pack에서 기록된 파일은 거부, wcount는 파일을 믿지 않고
  재계산. 파일 = 헤더(매직+버전+pack 지문: 소스
  size/mtime·err_total·check_cnt) + status + wcount. 같은 DB의
  재-pack에는 리뷰가 유지되고, 지문 불일치(DRC 재실행 = 에러 번호
  재부여)면 기존 자동 저장을 `.stale-<시각>`로 옆에 치우고 새로
  시작(리뷰 기록을 지우지 않음). 첫 생성 시 pack에 남은 구-방식
  내장 status는 시드로 승계. 결과 폴더가 읽기 전용이면 시스템 임시
  디렉터리로 폴백(stderr 안내 — 이때는 save as로 남길 것), 그마저
  안 되면 구-방식(pack 제자리 기록) 최후 폴백.
- **에러 note = 리뷰어별 flateyes `.fe` 사이드카**(2026-08-28,
  D10): `n`으로 선택/현재 에러에 **공유 note** 입력. 저장 위치 =
  pack 옆 `.<db>.notes.<리뷰어>.fe`(waive와 같은 siting·리뷰어
  태그·읽기전용→임시 폴백). 파일은 **유효한 flateyes 주석
  사이드카** — note마다 멤버 에러의 um 중심에 `text=` 주석(ppu=1
  unit=um)을 써서 flateyes와 미래 drawing이 그대로 렌더하고,
  flateyes가 무시하는 floe 전용 두 줄이 나머지를 담는다:
  `floe_pack=<size>,<mtime>,<err_total>`(지문),
  `floe_note=<gid,gid,…>|<escaped 텍스트>`(공유 note+멤버). floe는
  `floe_note=`(전역 에러 id 키)로 정본 복원, `text=`는 렌더 미러.
  삭제 = 빈 내용 입력 또는 "clear note of selection"(그룹 선택
  일괄). **캔버스 표시**: 더블클릭(점프)된 에러의 note를 화면
  좌상단 반투명 패널(flateyes note 스타일)에 보이며(점프 마크가
  살아있는 동안), 룰러 거리칩과 같은 위젯이라 Tab이 오버레이를
  모두 끌 때(mode 2) 함께 숨는다(mode 1엔 점프 에러와 함께 유지).
  그리드 목록에서는 note 있는
  에러의 로컬 번호 앞에 `*`가 붙는다. note 편집 다이얼로그에는
  **내장 두벌식 한글 조합기**(Shift+Space 토글, `floe/hangul.py` —
  flateyes 이식, IME 없는 폐쇄망 호스트용)가 있다(게이트 D11).
  **영속
  기록은 명시적**: `save notes as…`/`load notes…`(같은
  `.fe` 포맷, load=전체 대체·타-pack 거부). `notes_list()`가 미래
  note-list 조회 표면(각 note의 텍스트+멤버 gid). drawing 기능
  추가 시 같은 `.fe`에 flateyes 주석으로 합류.
- **손상 방어**: 절단·오염 pack은 전부 "corrupt pack → 재-pack
  안내" ValueError로 정규화(섹션 경계·체크 범위 검증), 사이드
  pack이면 ASCII 폴백. 인덱서는 시작 시 잔존 `<out>.tmp*` 청소.
- **병렬 빌드**: 바이트 구간 분할 + 체크 헤더 투기 동기화 + 이음새
  검증 — **--jobs 무관 동일 바이트**(D5). 95MB 8코어 0.2s.
  기록은 `<out>.tmpw` → 완성 후 rename(원자적) — 재-pack이 기존
  pack(열린 뷰어 mmap 포함)을 truncate하지 않고, 실패 시 부분
  파일을 남기지 않음. 인코더 메모리는 최대 룰 크기와 무관:
  대형 룰(4M 에러 초과)은 bbox 프리패스 + qbox 블록 스트리밍
  2-pass, 블록 테이블은 임시 스풀(두 경로 바이트 동일 — D5b).
- **레이아웃 규율**: 섹션 배치가 바뀌면 헤더 version을 올리고
  리더는 현재 값만 수용(구 pack을 새 리더가 조용히 오독해 소형
  쿼리만 빗나갔던 사고의 재발 방지 — 거부 시 재-pack 안내).
- **v1 오프셋 사이드카는 폐기**(08-19 확정): waive 저장·공간 쿼리
  불가, 원본 .db 상시 동반(139G 실측 = 20G 인덱스 + 원본 139G).
  잔존 v1 파일은 stderr 안내 후 ASCII 폴백, `floe-index drc`로
  재변환. 이름은 2026-09-16부터 db 옆 숨김 파일 `.<db>.tray`
  (`floe/cachepath.py`; 그 전의 `<db>.ice`는 발견 시 자동 개명, waive·note
  사이드카는 db 이름 기준이라 그대로 맞는다). `.ice`는 지금 VFS 인덱스 폴더
  `.<src>.ice/`의 접미사다(2026-08-13까지는 레거시 타일 캐시 이름).

## 3. 뷰어 DRC 브라우저 (왼쪽 pane 상시 내장)

**열기** — open .db… 다이얼로그(.db만 표시, 로딩은 pack만; 부재/
스테일/구 레이아웃이면 **"Build it now?" 확인 후** 인덱싱 + 모달
로그 — load layout의 VFS 인덱싱과 같은 흐름), `--drc` 시작
옵션. 로드 직후 = 무선택 상태. 정보줄:
`파일명 [pack v4] — cell · 표시/전체 룰 · 에러 · svrf N/M`.

**룰 목록** — 이름 + `에러수/waived`(예: 30/20, 둘 다 O(1)).
- 검색 박스(목록 상단): 이름 부분일치 실시간 필터.
- 유형 콤보: SVRF 측정문 metric별 분류(width/space/notch/enclosure/overlap/extension/
  area/density/…; rules.json 필요, 다중 측정문 룰은 각 유형 매칭).
- All/Not Waived/Waived 콤보: status 기준(All은 에러 0 룰도 표시).
- 세 필터는 **교집합**. 룰 선택 = 열기(한 번에 한 룰).

**사용자 클러스터**(2026-10-05) — DB 옆 `results.db.clusters`가
있으면 자동으로 읽는다. 다른 경로의 파일이나 수정한 파일은 DRC 메뉴
`load clusters…`로 불러온다. UTF-8 텍스트 예:

```ini
# 번호는 에러 그리드와 같은 룰 내부 번호(1부터)
[M1.SPACE.1]
클러스터 1 = 1-1000000
클러스터 2 = 1000001-2000000, 2500000
클러스터 3 = 2000001-2499999
```

- 해당 룰만 펼침 화살표가 있는 트리가 되며, 클러스터는 파일의 첫
  등장 순서대로 표시된다. 파일에 없는 룰은 기존 목록을 유지한다.
- 부모 룰 선택 = 전체 에러, 하위 클러스터 선택 = 그 클러스터의 에러.
  번호는 원래 룰 내부 번호를 유지한다. 빠진 에러는 `Unclustered`
  (미분류) 항목에 자동으로 모인다. 각 행은 `전체/waived` 수를 표시한다.
- 범위는 양 끝을 포함한다. 같은 클러스터 이름을 여러 줄에 반복하면
  합쳐지므로, 흩어진 번호도 긴 한 줄 없이 생성할 수 있다.
- 페이지 이동·`./,`·waive·in view·selected 필터는 클러스터 범위 안에
  적용된다. 선택 집합은 부모 룰과 각 클러스터마다 따로 보존한다.
- 범위는 개별 번호로 펼치지 않는다. `1-1000000`은 구간 하나로 저장하고,
  페이지의 번호와 도형만 읽는다. status 카운트는 첫 사용 시 계산하여
  캐시하고, waive 변경 때 영향받은 청크만 갱신한다.
- 없는 룰, 중복된 룰 이름 때문에 모호한 지정, 범위를 벗어난 번호,
  겹치는 소속은 파일명·줄 번호와 함께 거부한다. 한 에러는 한 클러스터에만
  속한다. DRC를 재실행해 번호가 바뀌면 파일도 다시 생성해야 한다.

문법과 성능 계약은 [포맷 규격](SPEC-FORMATS.ko.md)의 `<db>.clusters` 절에 정의한다.

**캔버스**(2026-10-05) — 선택한 **룰 전체**, 클러스터를 선택했으면
**그 클러스터 전체** 중 화면에 걸치는 에러를 표시한다. 그리드의 1000개
페이지와 독립적이므로 페이지를 넘겨도 마커 분포는 바뀌지 않는다.
waive·selected 필터는 적용하고, `in view`는 계속 목록 필터로 동작한다.

- 가까운 에러는 화면 짧은 변의 1/16(32–64px) 간격으로 먼저 묶는다.
  묶음 개수를 유지하기 위해 기존 화면 밀집도 집계 기준을 그대로 사용한다.
  최대 8192개인 요약 결과만 재집계하므로 원본 에러를 추가로 순회하지
  않으며 **에러 수·waived 수·전체 범위는 합산해 보존**한다.
- 묶음은 포함된 에러 전체의 외곽 범위(bbox)를 **속이 빈 사각형**으로
  표시한다. 사각형 크기는 에러 개수와 무관하며 서로 겹쳐도 추가로
  합치지 않는다. 축소 화면에서는 인덱스의 보수적인 외곽 범위를 사용해
  에러 위치를 빠뜨리지 않으며 실제 최소 사각형보다 약간 넓을 수 있다.
  확대하면 기존 정밀 좌표 복원 경로를 사용한다. 픽셀 경계도 바깥쪽으로
  반올림하며 점·선처럼 폭이나 높이가 없는 묶음에는 최소 표시 폭을 적용한다.
- 사각형 내부·테두리의 같은 위치를 반복 클릭하면 겹친 묶음을 순서대로
  선택한다. 현재 묶음은 흰 테두리와 `overlap 2/3` 같은 순번으로 표시한다.
  hover와 더블클릭은 현재 선택을 유지하며 더블클릭은 그 묶음을 확대한다.
  화면·범위 변경, 다른 곳 클릭, 개별 에러 선택, Tab 숨김 또는 Esc는
  순환 선택을 초기화한다.
- 묶음에 마우스를 올리거나 클릭하면 에러 수와 waived 수를 표시하고,
  더블클릭하면 확대한다. 확대하면 더 작은 구역/개별 에러로 나뉜다.
  같은 위치에 겹친 에러는 확대해도 하나의 묶음으로 남을 수 있다.
- 단일 에러는 5px 원, 포커스는 9px 원. not waived는 빨강,
  waived는 초록, 혼합 묶음은 사각형 테두리를 두 색으로 표시한다. 개별 마커의
  선택·점프·레이어 격리는 기존 동작을 유지한다. 실도형은 점프된 에러만 표시한다.
- 사각형 내부는 채우지 않아 겹친 영역에서도 레이아웃이 보인다. 단일
  마커 이미지와 화면 전체 마커 레이어를 캐시하며 선택 테두리만 덧그린다.
- pack의 qbox를 청크 단위로 집계하고 확대/화면 경계/단일 마커만
  실제 좌표로 정밀화한다. 개수는 정확하며 축소 시 묶음 위치/범위만
  근사한다. 좌표 캐시는 최대 32MiB, 출력과 임시 배열도 크기를 제한한다.
- 계산은 단일 백그라운드 작업자가 수행한다. 새 뷰가 오면 이전 작업을
  취소하고 오래된 결과를 버린다. 계산 중에는 정보줄에 `markers…`,
  완료하면 `에러 수 / 마커 수 in view`를 표시한다. 첫 정밀 확대에서
  조밀한 구역의 좌표를 읽는 비용은 발생할 수 있다.
- 박스 선택도 전체 룰/클러스터를 대상으로 정확한 에러를 조회한다.
  5000개를 넘으면 부분 선택하지 않고 더 작은 박스/확대를 안내한다.
  gold 선택은 기존처럼 개별 마커로 강조한다.

## 4. SVRF 룰 메타데이터 (.rules.json) — waive 판단 보조

**서브셋 파서**(`floe-index svrf`, `rust/cli/src/svrf.rs` — 2026-09-29
`floe/svrf.py`에서 이식, 파이썬 쪽은 사이드카 읽기(`load_rules`·
`rhs_operands`)만 남음): 지오메트리 연산 의미는 구현하지
않는다 — derivation은 우변 피연산자 이름만 그래프로 넣고, 체크의
원천 GDS 레이어는 그래프를 LAYER/LAYER MAP까지 폐쇄해서 얻는다.
- 전처리: INCLUDE 병합, #DEFINE/#IFDEF/#ELSE, VARIABLE·값 치환 —
  **실런과 동일한 -D 세트 필수**.
- 제약 추출 = **연속 체인 규칙**: 첫 비교연산자에서 시작하는 연속
  comparator+value 체인만(`> 0 < v` = 2건). 옵션 비교값(`ABUT<90`,
  `ABUT>0<90`, `OPPOSITE EXTENDED < x`)은 구조적으로 제외.
  비교연산자로 시작하는 다음 줄 = 직전 측정문의 연속(감싼 한계).
- 의도적 공백: DMACRO/CMACRO 비전개(카운트만), TVF는 생성된 SVRF를
  입력으로, 피연산자 줄바꿈 분리는 미지 히스토그램행. 새 덱은
  `--scan`(양쪽 #IFDEF 분기 워크, 인벤토리 출력)으로 구멍 확인.

**뷰어 연동**: db 옆 `<덱 베이스네임>.rules.json` 자동 부착(수동
DRC 메뉴 load SVRF rules…), 상세에 추가되는 블록:
```
constraint: ENC via1_drawn m6_drawn > 0 < 0.105
measured: 0.03990 um vs < 0.10500 · Δ 0.06510 (62.00000%)
layers: via1_drawn, m6_drawn
gds: 6/0, 15/0, 0/0, 63/63
derivation:
  via1_drawn = VIA1 NOT fill_excl
  fill_excl = FILLA OR FILLB
```
CD는 에러 마커에서 재측정한다. 직사각형은 가로·세로를 후보로 유지하고,
에지 쌍은 실제 최소 간격, 단일 에지는 길이, 면적은 마커의 신발끈
면적을 사용한다. 에지 쌍 룰러의 X/Y 보조 길이는 별도 CD 후보가 아니다.
추정이 필요한 경우 `estimated CD`, `CD candidates`, `CD selection`으로
선택값·후보·선택 이유를 표시한다. eqDRC 데이터는 사용하지 않는다.
그 외 더블클릭 레이어 격리와 룰 유형 필터의 분류 원천.

notch(`EXTERNAL … NOTCH`)와 두 레이어 overlap(`INTERNAL A B …`)도
동일한 마커 거리 측정 경로를 사용한다. `ENCLOSURE`는 enclosure와
extension 검사를 함께 포함하므로 둘을 문장만으로 임의 분리하지 않는다.
외부 사이드카의 `extension` metric도 거리 측정 대상으로 인식한다.

**사각형 CD 룰러**(2026-10-06): 가로·세로 각각에 오류 조건을 적용한다.
한 방향만 조건에 맞으면 해당 룰러만, 양쪽 모두 맞으면 두 룰러를 표시한다.
이는 그룹 계산에서 더 불리한 CD 한 개를 선택하는 정책과 별개다.
메타데이터가 없거나 미해석 제약·거리/형상 옵션이 남거나 맞는 방향을 찾지 못하면
두 방향을 유지한다. **area 전용 룰은 길이 룰러 대신 실제 폴리곤 면적을
`area 0.12345 µm²` 형식으로 표시한다.** 바운딩 박스 면적이 아니라
상세·그룹 계산과 같은 신발끈 면적이며, 삼각형·오목 폴리곤에도 적용한다.
area와 치수 검사가 섞인 룰은 면적 라벨과 기존 길이 룰러를 함께 유지한다.
면적을 구할 수 없는 에지 레코드에는 면적 라벨을 만들지 않는다.
면적 라벨은 일반 자동 룰러와 같이 Tab으로 숨기고 Esc/k로 지우며,
다른 에러로 점프할 때 교체한다. 뷰어 거리 칩과 수동 룰러를 그리는 중의 상태줄은 모두 소수점
다섯 자리로 표시한다. PNG의 임베드 룰러는 같은 방향을 선택하되, 표시
자릿수는 외부 flateyes의 설정에 따른다.
면적은 PNG에도 위 형식의 텍스트 주석으로 넣으므로 다섯 자리를 유지한다.
`NOTCH`/`SPACE` 분류 옵션만 있는 EXTERNAL은 방향 판정을 적용한다.
`REGION`, `OPPOSITE` 등의 형상·거리 조건과 `RECTANGLE ENCLOSURE`의
다중측면 조건을 Calibre처럼 재계산하는 기능은 포함하지 않는다.

**측정 차이 그룹**(2026-10-05) — SVRF 메타데이터가 있는 룰을
선택하면 에러 그리드 위에서 `Δ absolute` 그룹화가 자동으로 활성화된다.
`Δ ratio (%)`로 기준을 바꾸거나 `no grouping`으로 해제할 수 있다.

- 절대 차이 = `abs(측정 CD - 룰 한계값)`, 비율 차이 =
  `abs(측정 CD - 룰 한계값) / abs(룰 한계값) × 100`이다.
  두 기준 모두 0 이상의 위반 크기이며 최소값 요구의 부족분과
  최대값 요구의 초과분을 양수로 표시한다(2026-10-06).
  길이 계열은 `um`, 면적은 `um2`, 비율은 `%`로 표시한다.
- CD와 한계값을 먼저 소수점 다섯 자리로 반올림한 뒤 차이와 비율을
  계산한다. 반올림은 `ROUND_HALF_UP`(정확히 절반이면 0에서 멀어지는
  방향)이며 비율도 다섯 자리로 반올림한다. 상세 창과 그룹이 같은
  계산을 사용하며 CD 룰러의 수치 라벨도 소수점 다섯 자리로 표시한다.
- 기본 간격은 **해당 룰 전체의 CD 델타 범위에서 약 10개 그룹**이
  되도록 자동 계산한다. 절대 차이와 비율 차이를 각각 계산하며,
  클러스터나 waive 필터를 바꿔도 간격은 유지된다. 계산 중에는 입력란에
  `auto`, 완료하면 소수점 다섯 자리의 실제 간격을 표시하고 그룹 상태에
  `auto step`을 표시한다.
  내부적으로 다섯 자리 정수 단위에서 제약별 `[최솟값, 최댓값]` 범위의
  가장 큰 폭을 10등분하고 올림한다. 0을 기준으로 나누어 11번째 구간이
  생기면 간격을 늘려 제약마다 최대 10개 구간이 되도록 한다.
  최소 간격은 `0.00001`이다. 값 종류가 적거나 한 값뿐이면 실제 그룹은
  10개보다 적고, 서로 다른 제약 및 `Unmeasurable`은 따로 표시하므로
  룰의 총 그룹 수는 10개를 넘을 수 있다.
- 입력란에서 간격을 직접 지정하면 **룰별·모드별**로 수동값을 기억한다.
  `auto` 또는 빈칸을 입력하고 Enter / `set step`을 누르면 자동값으로
  돌아간다. 수동값은 현재 DRC와 SVRF 메타데이터를 사용하는 동안 유지되며,
  둘 중 하나를 새로 로드하면 초기화된다. 양수와 소수점 이하 최대 다섯
  자리만 허용한다. 끝에 붙인 0은 허용하지만 `0.000006` 같은 입력을
  임의로 반올림하지는 않는다. 비율 모드의 간격은 퍼센트 포인트 단위이다.
- 구간은 0을 기준으로 `[하한, 상한)`이다. 간격 `0.10000`이면
  델타 `0.09999`는 `[0.00000, 0.10000)`에, `0.10000`과
  `0.10001`은 `[0.10000, 0.20000)`에 속한다.
- **CD 후보 선택**(2026-10-06): 반올림 전 측정값에 SVRF의 오류
  출력 조건을 적용한다. 후보 하나만 조건에 맞으면 그 값을 선택한다.
  둘 다 맞으면 최소값 요구(오류 조건 `<`/`<=`)에는 작은 후보,
  최대값 요구(오류 조건 `>`/`>=`)에는 큰 후보를 선택한다. 직사각형의
  측정 방향을 룰로 추론한 값은 `estimated CD`로 표시한다.
  같은 측정문의 `> L < U`는 두 조건을 모두 만족하는 후보만 남기고,
  여러 후보가 남으면 상한 U를 기준으로 작은 후보를 선택하여 추정 표시한다.
  같은 문장 또는 줄 연속이라는 근거가 없는 서로 다른 측정문을
  임의로 하나의 구간으로 합치지 않는다. 후보가 없거나 서로 다른
  측정문에 동시에 맞아 기준을 특정할 수 없으면 `Unmeasurable`에 남긴다.
  경계 비교에는 좌표와 측정값의 부동소수점 연산 오차만 허용하며,
  다섯 자리 표시 단위로 먼저 반올림하지 않는다. 연산 오차 보정이
  판정을 바꾸거나 해석하지 못한 다른 제약이 남아 있으면 추정으로 표시한다.
  상세 창과 그룹이 같은 선택 함수를 사용하며 그룹에는 전체 소속 중
  추정 CD 개수도 표시한다(이 개수는 waive 필터와 독립적).
- 제약 번호가 다른 에러를 같은 그룹에 섞지 않는다. 그룹 이름의
  `Group #1`, `Group #2`는 현재 그룹 목록의 순번이며 페이지가 바뀌어도
  이어진다. `condition 2`는 SVRF 제약 번호로, 같은 제약에서 여러 델타
  구간이 생기면 반복될 수 있다. 측정 불가 그룹도 순번에 포함한다.
  스텝·클러스터가 바뀌면 그룹 순번도 바뀔 수 있지만 선택 복원에는
  제약 번호와 구간으로 된 내부 키를 사용한다. 비율 모드에서
  한계값이 `0.00000`이면 비율을 계산하지 않고
  `Unmeasurable / ratio unavailable`에 포함한다.
- 그룹 목록은 50개씩 넘겨 보며 `All errors`로 현재 룰 또는 파일 클러스터의
  전체 에러를 볼 수 있다. 한 그룹을 선택하면 그 그룹의 에러를 기존과
  같이 1000개씩 페이지로 표시한다. 파일 클러스터, waive, selected,
  in-view 필터와 함께 적용하고 룰 내부 번호는 바꾸지 않는다.
  그룹의 개수 표시는 waive 필터를 반영하되 0개가 된 그룹 행도 남겨
  선택한 그룹 범위를 유지한다.
  캔버스에는 현재 페이지와 관계없이 선택한 그룹 전체의 마커를 표시한다.
- 첫 측정은 백그라운드에서 현재 룰의 전체 에러를 읽는다. 이후 간격,
  기준 또는 파일 클러스터를 바꾸면 저장한 수치 측정을 재사용한다.
  측정값·소속은 수치 배열로 보관하고 화면에 필요한 그룹 행과 에러
  페이지만 만들어, 그룹 수가 많아도 GTK 행을 전부 만들지 않는다.

## 5. 성능 경로와 검증

전체 14억 건/룰당 천만 건 이상에서 룰 클릭 시 UI가 멈춘다는 보고에 따라
다음 경로를 변경했다. 실데이터는 공유받지 않았으며 아래 수치는 합성 검증이다.

- 에러 그리드는 번호·상태만 읽는다. 페이지의 1000개 도형을 미리 디코딩하던
  사용되지 않는 캐시를 제거했다. 실제 형상은 점프나 마커 조회 때 읽는다.
- packed 룰이 10만 건 이상이면 CD 측정·그룹 생성과 마커 조회를 별도 프로세스에서
  처리한다. GUI 스레드는 요청과 완료된 작은 결과/메모리 매핑만 교환한다.
  같은 규모의 `in view` 필터 조회도 별도 프로세스로 옮겼다.
- `.results.db.analysis/`에 룰별 공간 계층·원본 번호 posting, CD 측정표와
  절대/비율/수동 스텝별 그룹을 저장한다. 룰을 다시 선택하거나 뷰어를 다시 열어도
  완료된 측정표를 재사용한다. 원래 `.tray`와 리뷰 파일 포맷은 유지한다.
  pack 식별자·제약 조건·계산 버전으로 유효성을 검사하고 완료본만 원자적으로 공개한다.
- 공간 계층은 기존 보수적 qbox로 최대 깊이 8의 쿼드트리를 구성한다. 화면 안에
  완전히 포함된 작은 노드는 저장된 개수로 집계하고, 경계와 정밀 확대 영역은
  실제 도형으로 확인한다. 위치가 섞인 실제 pack 형식의 합성 1000만 건에서
  전체 집계는 3.280초 → 0.029초, 다음 화면 크기 변경은 0.014초였다.
  최초 생성은 3.847초, 공간 캐시는 41.65MiB였다(해당 머신의 warm 실행).
- 임의 클러스터/델타 그룹이나 waive 상태가 바뀌면 해당 선택의 공간 집계를
  처음 한 번 스캔한다. 같은 선택의 화면 이동에서는 프로세스 안의 집계를 재사용한다.
  작은 qbox 영역 안에 에러가 밀집한 정밀 확대는 여전히 후보 디코딩 비용이 든다.
  인덱스 저장이 불가능하면 마커는 별도 프로세스 안에서 기존 정확한 스캔으로 동작한다.
- CD 전처리는 처음 한 번 전체 형상을 측정해야 한다. 진행 중에도 페이지와 룰을
  바꿀 수 있고 이전 요청은 취소된다. 완료 전 임시 파일은 그룹으로 표시하지 않는다.
  별도 준비 명령은 [DRC-CLI.ko.md](DRC-CLI.ko.md)의 `drc-prepare`를 참고한다.
- 측정표는 에러당 13B, 기본 두 모드의 그룹은 각각 약 8B/error(룰 ID가 uint32에
  들어가는 경우)이며, 전체 14억 건이면 약 40.6GB + 공간/그룹 디렉터리가 필요하다.
  수동 스텝·클러스터 변형은 추가 캐시를 만든다. 룰 단위 mmap으로 읽고, 정렬
  임시 파일과 리뷰 상태는 별도로 관리한다. `FLOE_DRC_ANALYSIS_ROOT`로 로컬 SSD
  저장소를 지정할 수 있다.

- 일반 목록의 카운트/페이지에는 **O(룰 크기) 경로 금지**: 카운트 = [wcount]
  O(1), 상태 필터 그리드 = lazy 서술자(`status_page`/`status_rank`
  — 전수 리스트 실체화 없음), 공간 필터 = query_rect 스트리밍.
  측정 차이의 최초 측정과 재그룹은 별도 백그라운드 작업이며, 완료한
  수치 측정은 현재 룰에서 재사용한다.
- GTK 대량 재빌드 규칙: **모델 분리(set_model None) + 선택 핸들러
  busy 가드** — ListStore.clear()의 행별 자동 재선택이 머신에 따라
  핸들러를 행마다 실행(1000룰 필터 전환 9.7s 실측)했던 원인.
- 원격/타 머신 증상은 `FLOE_DRC_PROF=1`([drcprof] 단계별 시간)로
  계측을 보내 확진한다 — 추측 금지.

## 6. 테스트 자산과 게이트

작은 수동 확인 샘플(2026-10-06)은 저장소 루트의 `sample.db`와
`sample.svrf`다. 8개 룰, 38개 합성 에러이며 `sample.oas`를 함께 열면
캔버스의 CD/면적 표시까지 확인할 수 있다. 실제 Calibre 실행 결과는 아니다.
`sample.svrf.rules.json`과 `sample.db.clusters`도 함께 둔다.

```sh
python -m floe2 view sample.oas --multi --drc sample.db
# SVRF 또는 DB를 수정한 경우 재생성:
rust/target/release/floe-index svrf sample.svrf
rust/target/release/floe-index drc sample.db
```

룰 메타데이터와 클러스터는 자동으로 연결된다. 수동으로 메타데이터를
열 때는 `sample.svrf.rules.json`을 선택한다.

| 룰 | 에러 수 | 확인할 동작 |
|---|---:|---|
| M1.SPACE.1 | 20 | 다섯 자리 CD, 절대/비율 델타, 임의 번호 클러스터 |
| M1.WIDTH.MIN | 3 | #1 가로, #2 세로, #3 양쪽 룰러; 작은 후보 선택 |
| M1.WIDTH.MAX | 3 | #1 가로, #2 세로, #3 양쪽 룰러; 큰 후보 선택 |
| M1.NOTCH | 3 | 줄바꿈 범위/NOTCH 옵션, 사각형 방향과 에지 간격 |
| VIA1.ENCLOSURE | 2 | 사각형 CD 0.02000, 에지 간격 0.02500 µm |
| M1.M2.OVERLAP | 2 | 두 레이어 INTERNAL 분류, CD 0.02000/0.01500 µm |
| M1.EXTENSION | 2 | ENCLOSURE 계열, CD 0.02000/0.03000 µm |
| M1.AREA | 3 | 사각형/삼각형/L자 면적 0.00400/0.00600/0.00360 µm² |

위 번호는 룰 내부 번호다. AREA의 절대 델타는 각각
0.00600/0.00400/0.00640 µm², 비율은 60/40/64%다.

```sh
# 실디자인 정렬 세트 (testchip_1g5.oas, 레이어 격리까지 검증)
.venv/bin/python tools/gen_drcdb.py data/testchip_1g5.drc.db \
  --checks 96 --max-errors 400 --die 0,0,10500,10500 --seed 7 \
  --layers M1,M2,M3,M4,M5,M6,VIA1,VIA2,POLY,ACTIVE,CONT,NWELL \
  --svrf-gds "M1=5/0,M2=7/0,M3=9/0,M4=11/0,M5=13/0,M6=15/0,\
VIA1=6/0,VIA2=8/0,POLY=3/0,ACTIVE=2/0,CONT=4/0,NWELL=1/0,\
FILLA=0/0,FILLB=63/63" \
  --pathname testchip.drc.cal --svrf data/testchip.drc.cal
# 부하 세트: drctest(1000룰) / drcbig(--zeros 20 --heavy 12만~25만)
```
`gen_drcdb.py`는 **룰 종류와 일치하는 에러 도형**(SPACE=엣지쌍 갭,
WIDTH=얇은 사각형, AREA=면적 미달, DENSITY=50×50 윈도)을 한계 미달
치수로 생성하고, `--svrf` 동반 덱은 한계 표기를 5가지 실덱 스타일
(공백/붙임/`> 0 <v`/VARIABLE/줄바꿈)로 순환한다.

게이트(validate_rust.sh 스위트): `validate_drc_ice.py` **D1~D7**
(pack==ASCII 적대 픽스처 · 디스패치/폐기 v1 폴백 · dedup+lazy ·
gen 왕복 · jobs 불변 · query_rect 브루트포스 대조 · status/wcount),
`validate_svrf.py` **R1~R5+R3b**(전처리 · 그래프 폐쇄 · 추출
엣지케이스 · 실덱 표현식 · 엔드투엔드 매칭 · 명령 계약 — floe-index svrf).

## 7. 미결 (사무실/실데이터 대기)

- 139GB 실덱 `floe-index drc` 실측: 크기(목표 1/10~1/30) ·
  시간(구 16분 대비) — 부족하면 도형 템플릿 사전·블록 압축 검토.
- 실제 Calibre의 waived 표기법 파악 → 매핑(현재 floe [status]가
  유일한 waive 정본, 실데이터는 전부 Not Waived로 취급).
- 실덱 `--scan`으로 SVRF 파서 스코프 보정(CMACRO 사용 여부,
  미지 문장 히스토그램).
- S4: known/intended 에러 분류, 기준내(Δ 여유) 자동 필터, waive
  보조 워크플로 — 실덱 데이터 확보 후 별도 계획.
